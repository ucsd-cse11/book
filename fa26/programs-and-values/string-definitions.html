Student: Huh. That was an error?
Prof: Yeah, you ran into an interesting detail here. The type int is spelled lowercase, but the type String is uppercase.
Student: Why?
Prof: Why questions are great. The Java-specific reason is unfortunately jargon-y in this case: because int is a primitive type and String is a reference type, and primitive types have lowercase keywords and reference types are usually written uppercase. See? Lots of jargon.
Student: I like jargon! I told you, I’m an expert in many things. Ready for anything. But honestly I don’t know what you just said.
Prof: On this point, that’s fine. Stay tuned. For now it’s enough to remember that String  and int are spelled that way. You can use String and int as types along with Pict.
Prof: Oh and I want to leave you with a reminder about a tricky case here. Say my program prints out age = 17 after I run it. What do I know about that definition?
Student: Well, it isn’t necessarily int age = 17;, you could have done, like int age = 9 + 8. But it’s a number, so it’s got to be that it’s type is int, right?
Prof: Run this and see for yourself:
Student: They look exactly the same. So age is a number and label is text, but I can’t see that from the output.
Prof: Right. The quotes in "17" are how you make a string literal in the program. But that’s just part of the program. A lot of places in Java (and many programming languages) will print out the string value without the quotes. When you want to know whether a name holds a number or a string, look at the type in its definition, not at what gets printed.
Student: Does it matter? They print the same, so maybe Java treats them the same.
Prof: It matters as soon as you do something with them. For instance, what would age + 1 be? And what about label + 1? Hold onto that question for the next step.
Here is the program from the top of this step with String spelled correctly, plus a definition for the radius. What happens when it runs? (You can use the editor above to experiment!))
String myColor = "red";
String size = "10";
Pict c = new Circle(size, myColor);
Pict r = new Rect(30, 40, myColor);
  1. A red circle with radius 10 and a red rectangle.
    "10" is a string, and Circle takes an int radius. Java does not read the text inside the quotes to see if it looks like a number.
  2. An error: Circle takes an int radius, and size is a String.
  3. An error, fixed by changing the definition to int size = "10";.
    Changing the type alone does not help. "10" is a string literal wherever it appears, so int size = "10"; is an error too. The fix is int size = 10;, with no quotes.
  4. An error: myColor is used twice, and a definition can only be used once.
    myColor is fine. It is a String, and both constructors take a String color. The problem is size.
