Student: Ah, ok, so you’re thinking like `int emptySeats()` as a method on `Theater`?

Prof: Right, and getting that right will teach us about arrays of arrays. What do you think the loop will look like?

Student: Well, it’s like a counter pattern, right? We learned about those.

Prof: Indeed. If we have a loop that just needs to look at all the elements of a 2d array and count them, we can use a **nested loop** that matches the idea of **nested arrays**:

```java
record Theater(boolean[][] seats) {
  int emptySeats() {
    int howMany = 0;
    for(boolean[] row: seats) {
      for(boolean seat: row) {
        if(seat) { howMany += 1; }
      }
    }
    return howMany;
  }
}
boolean[] top = { true, false, true, true, true, true };
boolean[] middle = { true, false, false, false, true };
boolean[] bottom = { true, true, false, false };
boolean[][] seats = { top, middle, bottom };
Theater theater = new Theater(seats);
int emptySeats = theater.emptySeats();
```


## [Sitting with Friends](2d-arrays-more.html)

Student: OK, now that we’ve done that, what does the program look like to check if there are enough seats next to each other?

Prof: Ah great question. I think this is a good one to break down into a helper and then answer the overall question. Let’s build it up. Back to the image – say we want 3 seats together. The top row has enough, right?

[image]

Student: Right.

Prof: Did you need to look at any of the other rows to determine that?

Student: I guess not?

Prof: That’s interesting, because **whether or not a row has enough seats** is just a property of one `boolean[]` array, not of the whole theater.

Student: I can see that.

Prof: And then if **any** row has enough seats next to each other, then the theater itself has such a row.

Student: Yeah, I buy that.

Prof: OK, so let’s write the helper first. What do you think it takes as arguments?

Student: I guess just `boolean[] row`?

Prof: Anything else? Will it always check for 3 seats in a row?

Student: Oh right, so I guess also an `int` for how many seats we want.

Prof: And in our simple example for now, what does it return?

Student: A single `boolean` – whether or not the row had enough seats

```java
record Theater(boolean[][] seats) {
  boolean rowHasSeats(boolean[] row, int target) {
    int consecutiveAvailable = 0;
    for(boolean b: row) {
      if(b) { consecutiveAvailable += 1; }
      else { consecutiveAvailable = 0; }
      if(consecutiveAvailable >= target) { return true; }
    }
    return false;
  }
}

boolean[] middle = { true, false, false, false, true };
boolean[] bottom = { true, true, false, false };
boolean[][] seats = { top, middle, bottom };
```


Prof: This one is worth tracing from the beginning! It has some interesting ideas. It’s kind of a counter loop, but it also has another pattern – a search that returns as soon as it finds the answer. The `return` in the loop returns from **the whole method**. So if we ever find `target` adjacent seats, we return `true` immediately. We only return `false` if we get through the whole array without finding a sequence like that.

Student: It’s also weird because we don’t use `seats` at all in the method. So we say `theater.rowHasSeats(top, 3)` but we never use any of the fields from `theater`.

Prof: That’s a good observation! Helper methods are often like that; they just work with the data they are given. The methods that call them will look up the right data for them to use.

Student: OK so let’s build the method that uses `seats`?

Prof: Right. I would say this is a search method on the seats array. It returns true as soon as it finds a row with enough seats, using the helper.

```java
record Theater(boolean[][] seats) {
  boolean rowHasSeats(boolean[] row, int target) {
    int consecutiveAvailable = 0;
    for(boolean b: row) {
      if(b) { consecutiveAvailable += 1; }
      else { consecutiveAvailable = 0; }
      if(consecutiveAvailable >= target) { return true; }
    }
    return false;
  }
  boolean hasSeats(int target) {
    for(boolean[] row: seats) {
      if(rowHasSeats(row, target)) { return true; }
    }
    return false;
  }
}
boolean[] top = { true, false, true, true, true, true };
boolean[] middle = { true, false, false, false, true };
boolean[] bottom = { true, true, false, false };
boolean[][] seats = { top, middle, bottom };
Theater theater = new Theater(seats);
boolean rowHasSeats = theater.rowHasSeats(top, 3);
boolean theaterHasSeats = theater.hasSeats(3);
```

Output:

```text

middle = [true, false, false, false, true]
bottom = [true, true, false, false]
seats = [[true, false, true, true, true, true], [true, false, false, false, true], [true, true, false, false]]
theater = Theater[seats=[[Z@8ca]
rowHasSeats = true
theaterHasSeats = true
```

Student: Huh, so it’s kind of like a nested loop, but the inner loop is inside another method.

Prof: That’s right! I think the tricky logic is mostly in the helper – the incremental counter. So I find that I can read this a little easier because each method has its own job.

Student: Could you write it as one bigger nested loop and get the same answers?

Prof: Absolutely. This breakdown is more about how I chose to think about the problem. There are many ways to make it work!

## [Rasters](raster.html)

Student: Prof, my friend took a different CS course and they said we’re representing images all wrong.

Prof: Oh? How so?

Student: The pictures in their class are all represented as arrays of arrays of colors. They call them pixels.

Prof: Ah, they are working with rasterized images!

Student: Huh?

Prof: We can have them, too! It’s a different way of thinking about a picture. Rather than having logical shapes placed on or next to each other, we think about the grid of pixels. Both are valid ways of thinking about an image. And our `Pict` objects can go back and forth to the array representation. Every `Pict` has a `render()` method. Let’s check it out:

```java
Pict rect = new Rect(3, 4, "red");
Raster rastered = rect.render();
```

Output:

```text
rect = Rect[width=3, height=4, color=red]
[image]
rastered = Raster[3x4]
[image]
```

Prof: They show up as the same image, but they have different internal representations. Note the `3x4` in the printed version of the Raster, which matches the size of the `Rect` it came from. We could create the same `Raster` by using its constructor:

```java
import java.awt.Color;
Pict rect = new Rect(3, 4, "red");
Raster rastered = rect.render();
Color[][] colors = {
  { Color.RED, Color.RED, Color.RED },
  { Color.RED, Color.RED, Color.RED },
  { Color.RED, Color.RED, Color.RED },
  { Color.RED, Color.RED, Color.RED }
};
Raster rastered2 = new Raster(colors);
```

Output:

```text
rect = Rect[width=3, height=4, color=red]
[image]
rastered = Raster[3x4]
[image]
colors = [[java.awt.Color[r=255,g=0,b=0], java.awt.Color[r=255,g=0,b=0], java.awt.Color[r=255,g=0,b=0]], [java.awt.Color[r=255,g=0,b=0], java.awt.Color[r=255,g=0,b=0], java.awt.Color[r=255,g=0,b=0]], [java.awt.Color[r=255,g=0,b=0], java.awt.Color[r=255,g=0,b=0], java.awt.Color[r=255,g=0,b=0]], [java.awt.Color[r=255,g=0,b=0], java.awt.Color[r=255,g=0,b=0], java.awt.Color[r=255,g=0,b=0]]]
rastered2 = Raster[3x4]
[image]
```

Student: Huh, interesting. What’s that `import` line for, and why are we using `Color.RED` instead of `"red"`?

Prof: The way `Raster` is represented uses some of the built-in Java types for doing drawings. The `Pict` constructors like `Rect` and `Circle` have some conveniences for using string names, but once we get to `Raster` we will be talking more about colors as Java sees them. This is part of the [java.awt](https://docs.oracle.com/javase/8/docs/api/java/awt/package-summary.html) library.

Student: OK, I see. When it prints it’s saying `r`, `g`, and `b`. What’s that about?

Prof: Great question, it is called the [RGB](https://www.figma.com/resource-library/what-is-rgb/) model of colors. `R` for red, `G` for green, and `B` for blue. Combining different amounts of red, green, and blue can express a wide array of colors, and its one of the standard ways computers represent them. So a raster is an array of arrays of colors, where each color has these three components. Since we used `Color.RED`, that’s all red. You could create your own colors with different amounts! Here’s the same example with a nice mix of blue and green:

```java

Pict rect = new Rect(3, 4, "red");
Raster rastered = rect.render();
Color teal = new Color(0, 100, 150);
Color[][] colors = {
  { teal, teal, teal },
  { teal, teal, teal },
  { teal, teal, teal },
  { teal, teal, teal }
};
Raster rastered2 = new Raster(colors);
```

Output:

```text

[image]
rastered = Raster[3x4]
[image]
teal = java.awt.Color[r=0,g=100,b=150]
colors = [[java.awt.Color[r=0,g=100,b=150], java.awt.Color[r=0,g=100,b=150], java.awt.Color[r=0,g=100,b=150]], [java.awt.Color[r=0,g=100,b=150], java.awt.Color[r=0,g=100,b=150], java.awt.Color[r=0,g=100,b=150]], [java.awt.Color[r=0,g=100,b=150], java.awt.Color[r=0,g=100,b=150], java.awt.Color[r=0,g=100,b=150]], [java.awt.Color[r=0,g=100,b=150], java.awt.Color[r=0,g=100,b=150], java.awt.Color[r=0,g=100,b=150]]]
```

Student: OK, I think I see. That’s a lot of typing to build a really small image, though, right?

Prof: Indeed! We will need a lot more infrastructure to build up interesting images from this. But there are also things we can do with `Raster` that would be hard to do any other way.

```text
[image]
```


Prof: One thing we can do with rasters is calculate interesting image properties. For example, we can get the **average color** of an image.

Student: The average color?

Prof: Right, we can add up all the red, blue, and green channels independently, then divide by the number of pixels. A very blue picture should have a mostly-blue result, a very purple picture would show blue and red, and so on.

Student: OK, I guess that’s interesting.

Prof: It will be a good start for other raster methods. We are going to need something new and useful: an indexing for loop. We’ve seen for-each loops (what we just called a `for` loop before) that work over the elements of an array, but it turns out `Raster` only has `colorAt`, no way to use a for-each loop that goes element by element.

Student: So what does an indexing for loop look like?

Prof: The idea is that the loop variable tracks an index into an array or other structure (like a `Raster`).

```java
for(int index = init; index < maxIndex; index += increment) { ... }
```

The name `index` is your choice, people use `i` and `j` or `counter`, things like that, as well. The value `init` is some starting point; `0` is common for starting at the beginning of an iteration. `maxIndex` is often the length of an array or structure, but some iterations might stop early. Then `increment` is how many indexes to “move ahead” by, which is often `1` but could be different values as well.

Enough talking, let’s see it in action. This will be an **indexed, nested, running-sum loop** that tracks a sum for each of red, blue, and green:

```java
import java.awt.Color;
Color averageColor(Raster raster) {
  int r = 0, g = 0, b = 0;
  int height = raster.height();
  int width = raster.width();
  for(int rowIndex = 0; rowIndex < height; rowIndex += 1) {
    for(int colIndex = 0; colIndex < width; colIndex += 1) {
      r += raster.colorAt(colIndex, rowIndex).getRed();
      g += raster.colorAt(colIndex, rowIndex).getGreen();
      b += raster.colorAt(colIndex, rowIndex).getBlue();
    }
  }
  int totalPix = width * height;
  int rAvg = r / totalPix, gAvg = g / totalPix, bAvg = b / totalPix;
  return new Color(rAvg, gAvg, bAvg);
}
Raster salk = ImageIO_.load("images/salk.png");
Color salkAvg = averageColor(salk);
Color[][] redblue = { { Color.RED, Color.BLUE, Color.BLUE }, { Color.RED, Color.RED, Color.BLUE } };
Color redblueAvgs = averageColor(new Raster(redblue)); // should be 127, 0, 127
```

Output:

```text
salk = Raster[240x189]
[image]
salkAvg = java.awt.Color[r=81,g=91,b=109]
redblue = [[java.awt.Color[r=255,g=0,b=0], java.awt.Color[r=0,g=0,b=255], java.awt.Color[r=0,g=0,b=255]], [java.awt.Color[r=255,g=0,b=0], java.awt.Color[r=255,g=0,b=0], java.awt.Color[r=0,g=0,b=255]]]
redblueAvgs = java.awt.Color[r=127,g=0,b=127]
```

Prof: Whew, that was a lot. What questions do you have?

Student: Have we seen `getRed` and `getBlue` before?

Prof: No, I just know those are methods on `Color` that get back those components.

Student: Why is it `colIndex, rowIndex` and not the other way around?

Prof: That’s just the way `Raster.colorAt` is defined; it takes an “x” and then a “y” coordinate.

Student: And unlike picts, the 0 value for y is at the top?

Prof: That’s right, to match Java’s underlying image library more closely.

Student: So the Salk picture is very slightly more blue than anything else?

Prof: Yup.

Student: Could I have nested the loops the other way?

Prof: For this loop, yes. We’re only adding things up, so it doesn’t matter whether we go across each row, one row at a time, or down each column, one column at a time. Either way every pixel gets added in exactly once.

Student: OK! Indexing for loops and rasters. Cool stuff.

## [Negatives](more-filters.html)

Prof: Now that we have this loop idea, we can do interesting things like mess with the colors. Have you ever heard of a **negative** of an image?

Student: Maybe? Like where the colors are all weird?

Prof: Right. The negative is the result of “inverting” all the colors. So if `r` was 50 in the original, make it 205 in the negative. The arithmetic is `255 - c` for each color channel `c`. This turns, say, purple (red and blue, no green) into green, just like on a color wheel.

Student: Let’s see what it looks like?

Prof: For now, I’m going to set this up to return a **new** `Raster` to show a builder style for these (we could also use a updater style).

```java
import java.awt.Color;
Color negate(Color c) {
  int negR = 255 - c.getRed();
  int negG = 255 - c.getGreen();
  int negB = 255 - c.getBlue();
  return new Color(negR, negG, negB);
}
Raster negative(Raster raster) {
  Color[][] negativePix = new Color[raster.height()][raster.width()];
  for(int row = 0; row < raster.height(); row += 1) {
```
