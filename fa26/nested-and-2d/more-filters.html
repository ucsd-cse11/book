Negatives

Prof: Now that we have this loop idea, we can do interesting things like mess with the colors. Have you ever heard of a negative of an image?
Student: Maybe? Like where the colors are all weird?
Prof: Right. The negative is the result of “inverting” all the colors. So if r was 50 in the original, make it 205 in the negative. The arithmetic is 255 - c for each color channel c. This turns, say, purple (red and blue, no green) into green, just like on a color wheel.
Student: Let’s see what it looks like?
Prof: For now, I’m going to set this up to return a new Raster to show a builder style for these (we could also use a updater style).
Student: I see, so it has its own definition of “inverting” and it applies that to every color. And it returns a new Raster?

After negateInPlace(r) runs on the r above, what is colors[0][0]?
  1. Color.RED, still: new Raster(colors) copied the colors into the raster’s own grid, so setColorAt changes that copy, not colors.
  2. The negative of red, java.awt.Color[r=0,g=255,b=255].
