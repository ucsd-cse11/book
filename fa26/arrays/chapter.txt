## [Arrays and Loops](loops.html)

Prof: There are actually a lot of ways to do this in Java. We’ll use a loop; it’s one of the most common and it works well with arrays.

Student: Finally, real code!

Prof: Hey, everything up to now was extremely real, we watched it all run and everything!

Student: Just show me the loop, please!

Prof: Fine. First tell me the plan for this method body, though.

Student: The plan?

Prof: Yeah. Loop plans over arrays will often say something like “for each element of the array, the code will…”

Student: OK. For each point, the code will get its distance to the target and check if it’s closer than… the other… closer than something.

Prof: Right, we need a point of comparison. This is a kind of accumulator loop because it’s going to track a value that “accumulates” some information over time. Here I’d call it a best-so-far accumulator, which tracks “the closest point we’ve seen so far”.

Student: OK, so for each point, the code will get its distance to the target and check if it’s closer than the closest point we’ve seen so far.

Prof: And what does it do if we get something closer?

Student: I guess it… updates it?

Prof: Cool! Let’s put it all together.

```java
record Point(double x, double y) {
  // distance from this point to other
  double distanceTo(Point other) {
    double dx = x - other.x;
    double dy = y - other.y;
    return Math.sqrt(dx * dx + dy * dy);
  }
}
record Positions(Point[] points) {
  Point closestTo(Point target) {
    Point closest = points[0];
    for(Point p: points) {
      if(p.distanceTo(target) < closest.distanceTo(target)) {
        closest = p;
      }
    }
    return closest;
  }
}
Point p1 = new Point(3.0, 4.0);
Point p2 = new Point(7.0, 8.0);
Point p3 = new Point(5.0, -1.0);
Point[] parray = { p1, p2, p3 };
Positions posns = new Positions(parray);
Point closestOrigin = posns.closestTo(new Point(0.0, 0.0));
Point closesttTopRight = posns.closestTo(new Point(9.0, 9.0));
```

Output:

```text
p1 = Point[x=3.0, y=4.0]
p2 = Point[x=7.0, y=8.0]
p3 = Point[x=5.0, y=-1.0]
parray = [Point[x=3.0, y=4.0], Point[x=7.0, y=8.0], Point[x=5.0, y=-1.0]]
posns = Positions[points=[LPoint;@78a]
closestOrigin = Point[x=3.0, y=4.0]
closesttTopRight = Point[x=7.0, y=8.0]
```

Student: Wow, that’s so interesting. There’s a lot going on!

Prof: Indeed. We just saw two things at once:

- Assignment – the definition of `closest` **starts** as the first value in the array, and then **changes** when we use `closest = p`
- A `for` loop – the syntax `for(Point p: points) { /* loop body */ }`. It runs the loop body once for each element of `points`, and each time it runs, the next element is stored in `p`.

These two things tend to go together in programming: many loops that we want to write only work with assignment.

And one other bit of jargon – a mathy name for a best-so-far loop that returns the element that is the “smallest” in some way is argmin, which you might see in other contexts. Here that “something” is the distance to a target.

Student: Cool!

Student: I could use some more practice and ideas with arrays.

Student: I’m game

Prof: Let’s imagine we want to print an array of strings, but numbered. So we have `{"apple", "banana"}` and we want to print it as

```
1. apple
2. banana
```

Student: I can see that being useful.

Prof: So we’ll set it up as a `record` with a field that’s a `String[]`, and then a method that builds this numbered string. One thing I need to mention first – `"\n"` means “newline” in Java. It’s a escape character that has a special meaning. It won’t print as `\n`, it’ll make the rest of the string go onto the next line when printed.

Student: Alright, I’ll be ready for it.

```java
record ItemList(String[] items) {
  String numberedList() {
    int counter = 1;
    String result = "";
    for(String item: items) {
      result = result + counter + ". " + item + "\n";
      counter = counter + 1;
    }
    return result;
  }
}
String[] groceryItems = { "eggs", "milk", "bread" };
ItemList groceries = new ItemList(groceryItems);
String list = groceries.numberedList();
```

Output:

```text
groceryItems = [eggs, milk, bread]
groceries = ItemList[items=[Ljava.lang.String;@7b4]
list = 1. eggs
2. milk
3. bread
```

Student: I see the `\n`, that is making them show up on separate lines. And when you do `+ counter` that’s concatenating the number in?

Prof: That’s right. So this example is really using two loop patterns together. The counter is **always** increasing by 1 in this case (not conditionally like in our other counters), and it’s used as part of the accumulated `result`.

Student: OK I’m liking these patterns. What are some other ones?

Prof: Great let’s keep going. Sometimes you want to take an array and produce a **new** array with a value calculated from each element of the original array. That requires some new thinking. ```

Student: OK, I see. So we’re going to try to write `String[] emails(String domain)`?

Prof: That’s right, and we need one more feature of arrays to handle it. The pattern here is called builder, and the new feature is **changing** an element of an array `arr[i] = v` where `arr` is an array and `i` is an integer. That’s called array update, and it’s how we make sure the `null` values are all replaced with the values we want before returning the new array.

Student: OK, so we make the array at the top, kind of like we initialized the totals or counters, and then we update in a loop?

Prof: Yup, that’s right. Like with `numberedList`, we combine it with a counter, so that we can refer to indices correctly. Here the counter is used as the index for the array update

```java
record Student(String displayName, String username, String id) {
  String email(String domain) { return username + "@" + domain; }
}
record CourseRoster(Student[] students) {
  String[] emails(String domain) {
    String[] emailStrings = new String[students.length];
    int index = 0;
    for(Student s: students) {
      emailStrings[index] = s.email(domain);
      index += 1;
    }
    return emailStrings;
  }
}
Student ada = new Student("Ada Lovelace", "alovelace", "A10000001");
Student alan = new Student("Alan Turing", "aturing", "A10000002");
Student grace = new Student("Grace Hopper", "ghopper", "A10000003");
Student[] enrolled = { ada, alan, grace };
CourseRoster cse11 = new CourseRoster(enrolled);
String[] ucsdEmails = cse11.emails("ucsd.edu");
```

Output:

```text
ada = Student[displayName=Ada Lovelace, username=alovelace, id=A10000001]
alan = Student[displayName=Alan Turing, username=aturing, id=A10000002]
grace = Student[displayName=Grace Hopper, username=ghopper, id=A10000003]
enrolled = [Student[displayName=Ada Lovelace, username=alovelace, id=A10000001], Student[displayName=Alan Turing, username=aturing, id=A10000002], Student[displayName=Grace Hopper, username=ghopper, id=A10000003]]
cse11 = CourseRoster[students=[LStudent;@919]
ucsdEmails = [alovelace@ucsd.edu, aturing@ucsd.edu, ghopper@ucsd.edu]
```

Student: Interesting. So it returns the whole array.

Prof: Right. The `new String[students.length]` makes a brand new array, and the loop fills it in with string values from the results of the `.email` method.
