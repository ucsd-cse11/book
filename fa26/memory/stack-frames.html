Student: Yeah. What’s going on with the stack there?
Prof: Oh sharp eye! Right, so this is a program with a main method. That method is called to start the program. In this case, we didn’t have any definitions of values at the top level, so that’s empty. All the action is happening in main’s stack frame.
Student: Stack frame?
Prof: Every time a method is called, Java sets aside space for its parameters and its variables (the definitions in the method body) in what’s called a stack frame. So here we’re seeing that the two arrays were created inside main, which was called from the top level.
Student: Huh. OK. So that happens for all methods? Or is this just a main thing?
Prof: For all methods. It’s true even if we call some methods from the top level. For example if we have a builder pattern, there are some interesting aspects to the memory diagram:

  double area() {
    double radius = inches / 2;
    return radius * radius * Math.PI;
  }
}
String shop = "Trash Panda Pizza";
void main() {
  Pizza big = new Pizza(16, 1000);
  double bigArea = big.area();
