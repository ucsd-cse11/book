```java
record ImageData(String keywords, String fileType) {
```

Student: Wait a second, what does `this` mean?

Prof: When we use the `this` keyword, we are referring to “the record that this method was called on.” So if you were to write `i1.matchesExtension("png")`, Java runs the method body with `this` standing for `i1`. So `this.fileType` refers to the `fileType` of `i1`.

Student: Ok, I see. So I need to make sure to use `this` in my `hasWidth` method.

```java
record ImageData(String keywords, String fileType, int width, int height) {
  boolean matchesExtension(String ext) {
    return this.fileType.equals(ext);
  }
  boolean hasWidth(int w) {
    return this.width.equals(w);
  }
}
ImageData i1 = new ImageData("cat sleeping", "png", 640, 480);
boolean width640 = i1.hasWidth(640);
```

Output (compile error):

```text
line 6: error: Cannot invoke equals(int) on the primitive type int
```

Student: Uhm, what did I do wrong. You taught me that I should be using `.equals()`, like I did when writing the `matchesExtension` method.

Prof: Not quite. Here’s what’s going on: `.equals(...)` is a **method call**, and methods must be called on objects. A primitive value like an `int` **does not have methods**, which is what the compiler means by “primitive type” in that error message. For primitives, `==` already compares the numbers themselves.

Student: So `.equals()` cannot be used in this case, so I should go back to using `==`.

```java
  boolean hasWidth(int w) {
```

Student: Hmm, I only know how to check one thing at a time. I can use `if` statements, one for the width and then inside another one for the height. Can I do that here?

Prof: Try it and see.

```java
record ImageData(String keywords, String fileType, int width, int height) {
  boolean matchesExtension(String ext) {
    return this.fileType.equals(ext);
  }
  boolean hasWidth(int w) {
    return this.width == w;
  }
  boolean largerThan(int minWidth, int minHeight) {
    if (this.width >= minWidth) {
      if (this.height >= minHeight) {
        return true;
      }
    }
    return false;
  }
}

boolean bigEnough = i1.largerThan(600, 400);
boolean tooWide = i1.largerThan(700, 400);
boolean tooTall = i1.largerThan(600, 500);
```

```text

bigEnough = true
tooWide = false
tooTall = false
```

Prof: It does work, and that’s a perfectly good way to write it out.

Student: Hmm, but the answer is `true` when both checks pass, and the order of the width and the height check doesn’t really matter. That feels like it should be shorter.

Prof: It can be. Try taking both of those checks and using `&&` between them. Remember that the return just needs to be an expression that is `true` or `false`, it doesn’t necessarily have to be written out as `return true`.

```java
record ImageData(String keywords, String fileType, int width, int height) {
```

## [Queries as Data](queries-as-data.html)

Student: Ok, so how do I “pass around queries like values”? I don’t get that.

Prof: First we have to talk about a new concept called an interface. An interface is a way to describe shared functionality across records. So in our `ImageData` example, what do all of the methods we have been writing share?

Student: Hmm, I guess we are asking a true/false question.

Prof: Correct, but go into more detail. What are we saying is true or false?

Student: Well, in `matchesExtension` we were checking whether the extension matches a certain file type, and in `largerThan` we are checking whether the size is larger than some value… which is a kind of matching as well. So really, it’s all checking for matches.

Prof: Exactly. Here, I will show you an example and we can work through it together. What new keywords do you notice in this code snippet?

```java
record ImageData(String keywords, String fileType, int width, int height) {}

interface ImageQuery {
  boolean matches(ImageData img);
}

record HasExtension(String ext) implements ImageQuery {
  public boolean matches(ImageData img) {
    return img.fileType().equals(this.ext);
  }
}

record LargerThan(int minWidth, int minHeight) implements ImageQuery {
  public boolean matches(ImageData img) {
    return img.width() >= this.minWidth && img.height() >= this.minHeight;
  }
}

ImageData i1 = new ImageData("cat sleeping", "png", 640, 480);
ImageQuery isPng = new HasExtension("png");
ImageQuery isBig = new LargerThan(600, 400);
boolean pngResult = isPng.matches(i1);
boolean bigResult = isBig.matches(i1);
```

Output:

```text
i1 = ImageData[keywords=cat sleeping, fileType=png, width=640, height=480]
isPng = HasExtension[ext=png]
isBig = LargerThan[minWidth=600, minHeight=400]
pngResult = true
bigResult = true
```

Student: Well, there is that `interface` word you mentioned: you created an `ImageQuery`. It looks like a record, but it doesn’t seem to be storing anything. And I think you forgot to write the code for the `matches` method!

Prof: Hmm, you’re right. `ImageQuery` isn’t storing any data, is it? And the `matches` method doesn’t have a return statement… let’s keep going. What is the other detail you notice?

Student: You used a new keyword, `implements`, and you put it outside the record? When I read it out it says “record `LargerThan` implements `ImageQuery`.” And then each of the new records you created has a `matches` method with the same signature as in the interface.

Prof: Good noticing!

Student: But I don’t understand *why*. Why do you have to make `ImageQuery` if you are going to have to write out the method for `matches` every time anyway? In that case we could just make sure each record has the `matches` method and we could call `matches` on whatever we wanted?

Prof: Well, there is one other detail at the end. Notice how we are able to declare both of these records as an `ImageQuery`. How about you try writing out your idea and seeing what happens.

Student: Ok, I bet my way will work.

Prof: You’re right, for now. But, let’s see what happens when we get back to the idea of combining queries: check out what happens when I try to add this new record in. We said we wanted to check for relationships between queries, such as an `Or`.


Student: OK, but it has an error.

Prof: Right. What would you do to fix it? How can you change `Or` so that you can construct both `bigOrPng` and `pngOrJpg`?

Student: I guess I can’t. I have to pick either `HasExtension` or `LargerThan` for the fields of `Or`, and neither works for both combinat– OHHH! Wait so the interface helps with this?

Prof: Right! When we have `interface ImageQuery` and records that `implement ImageQuery`, we are allowed to use `ImageQuery` as **the type of any value that implements ImageQuery**. So the implements lines let us replace the field types of `Or` with `ImageQuery`. And **then** we can construct both versions.

Student: That’s so cool! And I bet with that we can do `And` and stuff too.

Prof: Indeed. Give it a try with `And` and `Not` included as well.

Student: Sure, I think I understand the format now.

```java
record ImageData(String keywords, String fileType, int width, int height) {}

interface ImageQuery {
  boolean matches(ImageData img);
}

record HasExtension(String ext) implements ImageQuery {
  public boolean matches(ImageData img) {
    return img.fileType().equals(this.ext);
  }
}

record LargerThan(int minWidth, int minHeight) implements ImageQuery {
  public boolean matches(ImageData img) {
    return img.width() >= this.minWidth && img.height() >= this.minHeight;
  }
}

record And(ImageQuery left, ImageQuery right) implements ImageQuery {
  public boolean matches(ImageData img) {
    return this.left.matches(img) && this.right.matches(img);
  }
}

record Or(ImageQuery left, ImageQuery right) implements ImageQuery {
  public boolean matches(ImageData img) {
    return this.left.matches(img) || this.right.matches(img);
  }
}

record Not(ImageQuery query) implements ImageQuery {
  public boolean matches(ImageData img) {
    return !this.query.matches(img);
  }
}

ImageData i1 = new ImageData("cat sleeping", "png", 640, 480);
ImageQuery pngOrJpg = new Or(new HasExtension("png"), new HasExtension("jpg"));
ImageQuery bigPngOrJpg = new And(new LargerThan(600, 400), pngOrJpg);
ImageQuery notPng = new Not(new HasExtension("png"));
boolean r1 = bigPngOrJpg.matches(i1);
boolean r2 = notPng.matches(i1);
```

Output:

```text
i1 = ImageData[keywords=cat sleeping, fileType=png, width=640, height=480]
pngOrJpg = Or[left=HasExtension[ext=png], right=HasExtension[ext=jpg]]
bigPngOrJpg = And[left=LargerThan[minWidth=600, minHeight=400], right=Or[left=HasExtension[ext=png], right=HasExtension[ext=jpg]]]
notPng = Not[query=HasExtension[ext=png]]
r1 = true
r2 = false
```

Student: You know, these interfaces are actually kinda nice. But wait a second, you never explained what `public` means? I guess I just started copying your record examples without thinking about it.

Prof: Good catch. `public` is an access modifier. It says who is allowed to use a method. A `public` method can be called by code anywhere.

Student: So why did I have to write it here? We have been calling methods all the time.

Prof: Methods in an interface must be `public`, since the whole point of an interface is that anyone holding an `ImageQuery` can call `matches` on it. A record that implements the interface isn’t allowed to make that method *less* available than the interface promised. Try leaving it off:

```java
}

    return img.fileType().equals(this.ext);
  }
}
```

Output (compile error):

```text
line 8: error: Cannot reduce the visibility of the inherited method from ImageQuery
```

Student: I see, the compiler complains that it “cannot reduce the visibility of the inherited method”.

Prof: Exactly.

Student: Ok, these interfaces are cool and all. But, I wish I didn’t have to type out `new And(new LargerThan(600, 400), new Or(new HasExtension("png"), new HasExtension("jpg")))`. That’s a lot of `new`s to keep track of.

Prof: You’re right. Perhaps you want something in the chaining style we talked about earlier? Something like `isBig.and(isPng)`? We will go over that next.

## [Growing ImageData](growing-imagedata.html)

Student: Now I want to expand my implementation of `ImageData`. With this new `ImageQuery` interface, that is much easier to do. How about I give each image a file size? I’ll call it `sizeKb` for size in kilobytes. I don’t really know how big a kilobyte is, but I checked my File Explorer on my laptop and it shows a size in KB next to a bunch of images I downloaded from Google.

Prof: Good idea, and nice job looking at real-world examples to base your new fields off of. But, before we add new fields, maybe we should look to see if there is anything we already have that we haven’t added a record for?

Student: Oh, there is that `String keywords` field that we haven’t been using. I’ll add a record for checking keywords as well.

Prof: Good idea. So what two new records are you going to create?

Student: For the file size, I’ll make a `SmallerThanKb` record that takes a kilobyte limit and checks if the file size is smaller than it. For the keywords I’ll make a `HasKeyword` record that takes a `String` word input and checks if it matches the keywords. Strings are compared with `.equals()`, so I’ll use that.

```java
record ImageData(String keywords, String fileType, int width, int height, int sizeKb) {}

interface ImageQuery {
  boolean matches(ImageData img);
}

record HasKeyword(String word) implements ImageQuery {
  public boolean matches(ImageData img) {
    return img.keywords().equals(this.word);
  }
}

record SmallerThanKb(int limitKb) implements ImageQuery {
  public boolean matches(ImageData img) {
    return img.sizeKb() < this.limitKb;
  }
}

void main() {
  ImageData i1 = new ImageData("cat sleeping", "png", 640, 480, 300);
  ImageQuery catQuery = new HasKeyword("cat");
  assertEquals(true, catQuery.matches(i1));
}
```

Output (failed):

```text
Exception in thread "Thread-0" org.opentest4j.AssertionFailedError: expected: <true> but was: <false>
	at org.junit.jupiter.api.Assertions.failNotEqual(Unknown Source)
	at org.junit.jupiter.api.Assertions.failNotEqual(Unknown Source)
	at org.junit.jupiter.api.Assertions.assertEquals(Unknown Source)
	at main(Unknown Source)
```

Student: That’s strange. The image’s keywords are `"cat sleeping"`, and I asked for `"cat"`, but the assertion failed. Is `.equals()` broken?

Prof: Nope! `.equals()` did exactly what you told it. It checks whether two Strings are *exactly* the same, and `"cat sleeping"` is not exactly `"cat"`.

Student: Oh, so should I change `String keywords` to be `String[] keywords` instead? Then I could use a loop to check if any of the String values are equivalent.

Prof: You could do that, but there is another option without changing the `ImageData` record. You want to know whether the keywords *contain* the word. Strings have a method for that: `keywords.contains(word)` returns `true` if the word appears anywhere inside the String.

Student: So I swap `.equals()` for `.contains()`. I still think `String[]` would be better… did you purposely make it a `String` so that you could teach me `contains()`?

Prof: Perhaps. Now let’s put the two new records to work. Remember how you didn’t like typing all those `new`s, and wished you could write `isBig.and(isPng)`? Look at the `ImageQuery` interface in the program below. It has three new methods, and each starts with a word you haven’t seen: `default`.

Student: What does `default` mean? The `matches` method had no body in the interface. Every record that implements `ImageQuery` had to have their own method body.

Prof: That’s the difference. A default method (a method with `default`) *does* have a body inside the interface, and every record that implements `ImageQuery` gets it without having to write it themselves. So we write it once, in the interface, instead of in `HasKeyword`, `SmallerThanKb`, `Not` and every other record.

Student: So `this` is whichever query I call `.and()` on? In `cat.and(light)`, `this` is `cat` and `other` is `light`?

Prof: Exactly. Here, try it out yourself.

```java
record ImageData(String keywords, String fileType, int width, int height, int sizeKb) {}

interface ImageQuery {
  boolean matches(ImageData img);

  default ImageQuery and(ImageQuery other) {
    return new And(this, other);
  }
  default ImageQuery or(ImageQuery other) {
    return new Or(this, other);
  }
  default ImageQuery not() {
    return new Not(this);
  }
}

record HasKeyword(String word) implements ImageQuery {
  public boolean matches(ImageData img) {
    return img.keywords().contains(this.word);
  }
}

record SmallerThanKb(int limitKb) implements ImageQuery {
  public boolean matches(ImageData img) {
    return img.sizeKb() < this.limitKb;
  }
}

record HasExtension(String ext) implements ImageQuery {
  public boolean matches(ImageData img) {
    return img.fileType().equals(this.ext);
  }
}

record LargerThan(int minWidth, int minHeight) implements ImageQuery {
  public boolean matches(ImageData img) {
    return img.width() >= this.minWidth && img.height() >= this.minHeight;
  }
}

record And(ImageQuery left, ImageQuery right) implements ImageQuery {
  public boolean matches(ImageData img) {
    return this.left.matches(img) && this.right.matches(img);
  }
}

record Or(ImageQuery left, ImageQuery right) implements ImageQuery {
  public boolean matches(ImageData img) {
    return this.left.matches(img) || this.right.matches(img);
  }
}

record Not(ImageQuery query) implements ImageQuery {
  public boolean matches(ImageData img) {
    return !this.query.matches(img);
  }
}

ImageData i1 = new ImageData("cat sleeping", "png", 640, 480, 300);
ImageQuery cat = new HasKeyword("cat");
ImageQuery light = new SmallerThanKb(500);
```

Prof: Here, I’ll write out a section of the Pict library so we can talk through it. I trimmed it down a little; the whole thing is in [`Pict.java`](../kit/Pict.java).

```java
interface Pict {
    int width();
    int height();

    default Pict beside(Pict other) { return new Beside(this, other); }
    default Pict above(Pict other) { return new Above(this, other); }
    // ... more default methods ...

    void draw(Graphics2D g, int x, int y);
}

record Circle(int radius, Color color) implements Pict {
    // ... plus constructors that accept a color name like "red" ...
    public int width() { return 2 * this.radius; }
    public int height() { return 2 * this.radius; }
    public void draw(Graphics2D g, int x, int y) {
        g.setColor(this.color);
        g.fillOval(x, y, 2 * this.radius, 2 * this.radius);
    }
}

record Beside(Pict left, Pict right) implements Pict {
    public int width() { return this.left.width() + this.right.width(); }
    public int height() { return Math.max(this.left.height(), this.right.height()); }
    public void draw(Graphics2D g, int x, int y) {
        int centerY = this.height() / 2;
        this.left.draw(g, x, y + centerY - this.left.height() / 2);
        this.right.draw(g, x + this.left.width(), y + centerY - this.right.height() / 2);
    }
}
```

Student: Ok, so `Pict` is an interface. And you gave it a `width` and `height` method. So all cases where we implement `Pict` will have a `width` and `height` as well.

Prof: Correct, what else do you notice?

Student: You used `default` just like we did with `ImageQuery`, but instead of using it for `And`, `Not`, `Or`, it’s being used for `beside` and `above`. Although I am a bit confused about the `Graphics2D` part? What is a `Graphics2D`? What are all these lines that say `g` mean?

Prof: For now let’s just treat `Graphics2D` as our way of actually drawing pixels on the screen. `Pict` describes what we want to draw, and `Graphics2D` is part of a library that handles the details of actually drawing it.

Student: So you are hiding things from me again?

Prof: Funnily enough, the creators of `Graphics2D` actually hid all this from me! When I wrote `Pict`, I didn’t have to think too much about how `Graphics2D` works. It abstracted away those details so I could focus on implementing all the shapes and relationships that I wanted `Pict` to have. Programmers rely on the work of others, especially when working on very complicated projects. We have also been using `assertEquals()` the same way, as code someone else wrote that we trust to do its job.

Student: This is a lot to keep track of.

Prof: Let’s just focus on `Pict` a bit more, and just treat the `Graphics2D g` section of the `draw` method as a canvas with a paint brush: when you hand it something, it draws it for you. We only use it inside `draw`, and only the simple records like `Circle` call `Graphics2D` methods directly. The records are what we are focusing on. They hold the data saying “a circle with a given radius and color” or “a circle, then a square beside it”. `Pict` is the type that lets all of them be used interchangeably. Notice that `Beside` holds two `Pict`s, in the same way `And` held two `ImageQuery`s. The drawing part is just what allows us to see and verify the result visually, but all the data is defined by us.

## [Building Your Own Pict](building-your-own-pict.html)

Student: Ok, time to make my own `Pict`! Mine will be called `Art`, so it doesn’t collide with the real one that we have been using so far.

Prof: Good plan. Drawing is the hard part of `Pict`, so let’s skip it. Let’s just focus on the size of your `Art`. Write that as an interface, plus one simple record like the `Rect` from `Pict.java`.

```java
interface Art {
  int width();
  int height();
}

record Block(int width, int height) implements Art {}

void main() {
  Art wall = new Block(3, 2);
  assertEquals(3, wall.width());
  assertEquals(2, wall.height());
}
```

Student: Wait, `Block` doesn’t have a `width` method. Did I need to write it?

Prof: Nope. Every record gets a method for each of its fields, with the same name. `wall.width()` is one of those, and it is what the interface asked for.

Student: Ok. So now I should add something like `Beside`. How about `SideBySide`?

Prof: Go ahead. What is the width of two pictures next to each other? What is the height?

Student: The widths add up, and the height is whichever is taller. And I want a `nextTo` method, like `beside`, so I don’t have to type `new SideBySide(...)`.

```java
interface Art {
  int width();
  int height();

  default Art nextTo(Art other) {
    return new SideBySide(this, other);
  }
}

record Block(int width, int height) implements Art {}

record SideBySide(Art left, Art right) implements Art {
  public int width() {
    return this.left.width() + this.right.width();
  }
  public int height() {
    return Math.max(this.left.height(), this.right.height());
  }
}

void main() {
  Art wall = new Block(3, 2);
  Art tower = new Block(2, 4);
  Art both = wall.nextTo(tower);
  assertEquals(5, both.width());
  assertEquals(4, both.height());
  assertEquals(7, both.nextTo(new Block(2, 1)).width());
}
```

Student: The last line is a `SideBySide` inside another `SideBySide`, and it still works.

Prof: Because `left` and `right` are `Art`s, not `Block`s. It’s the same trick as `And` holding two `ImageQuery`s. Now one that holds a single picture: a `Frame` that adds a border, one unit thick on every side, around another `Art`.

```java
interface Art {
  int width();
  int height();

  default Art nextTo(Art other) {
    return new SideBySide(this, other);
  }
  default Art framed() {
    return new Frame(this);
  }
}

record Block(int width, int height) implements Art {}

record SideBySide(Art left, Art right) implements Art {
  public int width() {
    return this.left.width() + this.right.width();
  }
  public int height() {
    return Math.max(this.left.height(), this.right.height());
  }
}

record Frame(Art inner) implements Art {
  public int width() {
    return this.inner.width() + 2;
  }
  public int height() {
    return this.inner.height() + 2;
  }
}

void main() {
  Art wall = new Block(3, 2);
  assertEquals(5, wall.framed().width());
  assertEquals(7, wall.framed().framed().width());
  assertEquals(7, wall.nextTo(new Block(2, 4)).framed().width());
}
```

Student: A frame of a frame is 4 wider, since each `Frame` asks the picture inside it for its width and adds 2.

Prof: Exactly, and the picture inside might itself be a `Frame` or a `SideBySide`. Each one only has to know about its own parts. That is the same design as `ImageQuery` and as the `Pict` library. It’s an interface that describes what every value can do, simple records, combinator records that hold other values of the interface, and `default` methods that build them.
