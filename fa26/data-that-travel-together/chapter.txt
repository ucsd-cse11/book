### What is `Pict`?

Prof: Yes, more or less, that’s a good observation! That’s why you see the fields in the record printing. The book just has a little extra special step where it shows the image, too. I wrote `record Circle(...) { ... }` in a place that gets loaded for all the book programs.

Prof: Actually, this is a good time to do a little more with images. There are a few more constructors for images I’d like to show you.

Student: OK!

Prof: First let’s show the `Above` constructor, which puts two images on top of one another:

```java
Pict trunk = new Rect(10, 20, "brown");
```

Prof: Right! And notice that the record for the `Above` also prints out, which shows that it is made of those two other images. - `Below(Pict bottom, Pict top)`
- `Beside(Pict left, Pict right)`
- `Overlay(Pict front, Pict back)`

Student: OK…


## [Methods for Repeated Computation](methods.html)

### Methods for Repeated Computation

Student: Professor, I am having fun with images, but so far it seems like we’ve just **defined data**, not actually written any programs that do work.

Prof: You’re right. It’s not an accident – a lot of object-oriented programming is about representing data, so we’ve gotten a bunch of practice with that! But now we’re ready to start defining **behavior**, not just specific data shapes and values.

Student: Yeah! The good stuff.

Prof: Let’s grab one of our earlier examples – a `record` representing a social media `Post`:

```java
record Post(String content, String author, int likes) {}
Post p1 = new Post("My AI agent hacked my fridge today", "naught-cool", 3461);
Post p2 = new Post("Happy Birthday Ava!!!", "birthdaybot", 7);
Post p3 = new Post("Anyone else smell microwaved fish in CSE again today?!", "pesca127", 33);
```

Output:

```text
p1 = Post[content=My AI agent hacked my fridge today, author=naught-cool, likes=3461]
p2 = Post[content=Happy Birthday Ava!!!, author=birthdaybot, likes=7]
p3 = Post[content=Anyone else smell microwaved fish in CSE again today?!, author=pesca127, likes=33]
```

Prof: Say we’re setting up a custom timeline where only **unpopular** posts are shown. We might want a way to check for posts that have very few likes. We could try to check that for **each one** of the examples by using operators like `<` and using field lookup with `.`. But I’m going to show a different way. We are going to **add to the `record`**, finally using the space in between those `{}`. In there, I’m going to put a method definition, which in this case is going to take a number of likes and return `true` if this post has fewer likes, `false` if it has more.

```java
record Post(String content, String author, int likes) {
  boolean hasFewerLikesThan(int compareLikes) {
    return likes < compareLikes;
  }
}
Post p1 = new Post("My AI agent hacked my fridge today", "naught-cool", 3461);
Post p2 = new Post("Happy Birthday Ava!!!", "birthdaybot", 7);
Post p3 = new Post("Anyone else smell microwaved fish in CSE again today?!", "pesca127", 33);
boolean p1Fewer10Likes = p1.hasFewerLikesThan(10);
boolean p1Fewer10000Likes = p1.hasFewerLikesThan(10000);
boolean p2Fewer10Likes = p2.hasFewerLikesThan(10);
boolean p3Fewer10Likes = p3.hasFewerLikesThan(10);
```

Output:

```text
p1 = Post[content=My AI agent hacked my fridge today, author=naught-cool, likes=3461]
p2 = Post[content=Happy Birthday Ava!!!, author=birthdaybot, likes=7]
p3 = Post[content=Anyone else smell microwaved fish in CSE again today?!, author=pesca127, likes=33]
p1Fewer10Likes = false
p1Fewer10000Likes = true
p2Fewer10Likes = true
p3Fewer10Likes = false
```

Prof: The new stuff going on here:

- A method definition has a few parts

  - The return type, in this case `boolean`, declares what type the method must return
  - The parameters are similar to the fields of a record: they each have a name and a type. We can use those names in the method body
  - The method body is between the `{}` after the parameters. It is one or more statements that compute and return something
  - We can refer both to the parameters (like `compareLikes`) and the fields (like `likes`) within a `record`’s methods.
- Then, in the examples, we have method calls. These have an object value (in this case all `Post` values) which we call the receiver, then a `.`, then the name of a method (in this case `hasFewerLikesThan`), followed by the arguments in parentheses: the values the parameters take on for this call. It’s a lot like using a constructor, but instead of `new ConstructorName`, it starts with `object.methodName`.

Student: OK, so each time we call `hasFewerLikesThan`, it’s plugging in the argument for the value of `compareLikes`?

Prof: That’s right. In the first example we’re getting the result of `p1.likes < 10` (`p1.likes` is `3461`, not less than `10`, so we get `false`). The next example compares it to `10000` instead, so it’s `true`. That continues for each example – each method call refers to the **fields** from the receiver, and the **arguments** that come in from the call. Similarly, inside a method body, calling a method using just its name (no receiver) calls it with the same receiver.

Student: OK, I think I sort of get it…

## [Convenience Methods](convenience-methods.html)

Student: OK I think I’m starting to get it a little bit now. Here’s a question – do all `record`s have methods?

Prof: Great question. Not all of them have them, but all of them *can* have them, and they’re often useful. Our images have them, for example. Some of them are called convenience methods because they do something you could do anyway, they’re just easier to type and read.

Student: Interesting, what does that look like?

Prof: So far we’ve put two images beside each other with `new Beside(pict1, pict2)`, right?

Student: Sure, I remember that.

Prof: Well there’s also a **method** called `beside`. Here’s its signature:

```java
Pict beside(Pict other)
```

You can think of it as being defined in every one of the records like `Circle` and `Rect` and so on. Here are two examples of using beside, one with the constructor and one with the method:

```java
Pict blue = new Rect(10, 20, "blue");
Pict white = new Rect(10, 20, "white");
Pict red = new Rect(10, 20, "red");
Pict frConstr = new Beside(new Beside(blue, white), red);
Pict frMethod = blue.beside(white).beside(red);
```

Output:

```text
blue = Rect[width=10, height=20, color=blue]
[image]
white = Rect[width=10, height=20, color=white]
[image]
red = Rect[width=10, height=20, color=red]
[image]
frConstr = Beside[left=Beside[left=Rect[width=10, height=20, color=blue], right=Rect[width=10, height=20, color=white]], right=Rect[width=10, height=20, color=red]]
[image]
frMethod = Beside[left=Beside[left=Rect[width=10, height=20, color=blue], right=Rect[width=10, height=20, color=white]], right=Rect[width=10, height=20, color=red]]
[image]
```

Student: Interesting! I like how the method version reads. But wait, there’s something really weird there. I thought the thing before the `.` in a method call had to be the name of a definition, like `blue`.

Prof: That’s a great observation. The whole expression `blue.beside(white)` evaluates to one `Pict` (a `Beside` object), and then **that** object is used to call `.beside(red)` – it is the receiver for that method call. It never got named by the program, but it does exist briefly. Just like how the first argument to `new Beside(____, red)` is a use of the `Beside` constructor that makes a blue-and-white-stripe image.

Student: Hmmm OK.

Prof: This specific style is called method chaining, where you use the result of a previous method call as the receiver of the next. You can always name the intermediate value if you want! It doesn’t have any special behavior. It’s just a nice way to write and read that line of code.

Student: I think I get it! So do those methods exist for all the constructors for images?

Prof: For all the ones that combine two images, yes! There’s `Pict above(Pict other)`, `Pict overlay(Pict other)`, and so on.

Student: Hey prof, I had a program where someone typed in email addresses, and I wanted to get the part before the `@`. Are there a bunch of `String.` methods like there are `Math.` methods?

Prof: Clever to ask it that way. There **are** a bunch of methods that do work on strings. Using `String` methods look a little more like what we’ve done for `Pict`.

```java
String email = "bochoa@ucsd.edu";

String beforeAt = email.substring(0, atIndex);
```

Output:

```text
email = bochoa@ucsd.edu
atIndex = 6
beforeAt = bochoa
```

Prof: There are a lot of [string methods](https://docs.oracle.com/javase/8/docs/api/java/lang/String.html) defined by Java, and they are used quite frequently.

Student: OK, that’s helpful. What does the `6` for `atIndex` mean?

Prof: The `indexOf` method returns the index where it finds the string. We say each character in the string is at an index, which starts at 0 and counts from the beginning of the string. In the example `b` is at index 0, `o` at index 1, `c` at index 2, and so on until the `@` at index 6.

Student: Got it. What are some common things people do with strings?

Prof: There are a few that jump to mind. One category is searching: checking if a string appears in another, in different ways. Like is it **anywhere** in the string, at the **start**, at the **end**, and so on:

```java

boolean isGmail = email.endsWith("gmail.com");
boolean startsWithBo = email.startsWith("bo");
boolean startsWithUCSD = email.startsWith("ucsd");
boolean hasAt = email.contains("@");
boolean hasSpace = email.contains(" ");
```

Output:

```text
email = bochoa@ucsd.edu
isUCSD = true
isGmail = false
startsWithBo = true
startsWithUCSD = false
hasAt = true
hasSpace = false
```

Student: I see. These return `false` when it’s not found – you used `indexOf` above to find the `@` – what happens if you search for something that isn’t there with `indexOf`?

Prof: Great question, you can try yourself!

Student: Oh, right! Well I can use your example and search for something that isn’t there, like an exclamation mark.


Output:

```text

```

Student: Huh, it returned `-1`. I guess otherwise it returns where in the string it found it?

Prof: Nice work. Another category of string operations are for transforming the string and giving a new one back:

```java
String typed = "  bochoa@ucsd.edu  ";
```

Student: OK, so there’s a lot we can do

Prof: Yup. Let’s try to put it into practice a bit. One thing we often want to do with strings is **case-insensitive search**. That is, you might search a course catalog for all the courses whose titles contain `"intro"`, but really you want it to match `"Intro"` or `"intro"`. A trick that’s often used there is to lowercase both the search term and the target string, and then use something like `contains` or `indexOf`:

```java
record Course(String title, int number) {
    boolean titleContains(String search) {
        String lowerTitle = title.toLowerCase();
        String lowerSearch = search.toLowerCase();
        return lowerTitle.contains(lowerSearch);
    }
}
Course cse11 = new Course("Introduction to Programming", 11);
Course cse110 = new Course("Software Engineering", 110);
boolean introInCse11 = cse11.titleContains("intro");
boolean introInCse110 = cse110.titleContains("intro");
boolean engInCse110 = cse110.titleContains("ENGINEERING");
boolean engInCse11 = cse11.titleContains("ENGINEERING");
```

Output:

```text
cse11 = Course[title=Introduction to Programming, number=11]
cse110 = Course[title=Software Engineering, number=110]
introInCse11 = true
introInCse110 = false
engInCse110 = true
engInCse11 = false
```
