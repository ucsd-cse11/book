Test yourself!
A program says:
record User(String username, int followerCount) {}

User fan = new User("tritonfan", 1200);
What prints for the fan definition?
  1. fan = User[username=tritonfan, followerCount=1200]
  2. fan = User[tritonfan, 1200]
    Each value is labeled with its field’s name.
  3. fan = new User("tritonfan", 1200)
    new User(...) is how the value gets built, not how it prints.
Here the values for new User are in a different order than the fields. Decide what will happen before you run it.
What happens?
  1. It doesn’t compile: the values for new User must match the fields in order — a String, then an int.
  2. It works: Java matches "tritonfan" to username because it’s the only String.
    Java matches values to fields by position, not by type. The first value goes to the first field, whatever it is.
  3. It works, and prints User[username=1200, followerCount=tritonfan].
    Each field has a name and a type, and the type is checked: username is a String, and 1200 is an int.

A program contains only this one line:
record Post(String content, String author, int likes) {}
What has it done?
  1. Set up the shape of a Post — three fields, each with a name and a type — but no Post exists yet.
  2. Made one Post, with empty content and author and 0 likes.
    A record line never fills in values. That’s what new Post(...) is for.
  3. Made three definitions: content, author, and likes.
    Those are the fields of a Post. They only get values when a Post is constructed with new. Compare String author = "tritonfan";, which defines a name and gives it a value at the same time.
  4. Nothing: it’s an error, because the fields have no values.
    Not a mistake — a record line on its own is exactly how we describe the shape. The values arrive with new.
