Dynamic Dispatch

Student: I’m starting to kind of understand something that’s happening here, but I want to talk through it.
Prof: Go for it.
Student: So in Pict.java, there’s this part of the render method that calls draw:
interface Pict {
    // ...
    default Raster render() {
        // ...
        var g = img.createGraphics();
        // ...
        draw(g, 0, 0);
        // ...

Pict.java, lines 30–45

Student: And I’m trying to figure out how Java knows which draw method to call. Because render is written inside the Pict interface, so how does Java know whether it is calling draw on a Circle or a Rectangle or a Beside or whatever? There’s nothing in the Pict interface that can know.
Prof: Oh that’s a terrific question. We can answer it with a pretty small memory diagram.

Prof: The key thing here is the instance referred to by this, which is the receiver of render. What class is that instance from?
Student: Rect, right? But the type of the variable r was Pict.
Prof: And that’s the key point – Java uses the class of the instance to find the method. Not the type you wrote down in the program. The name of the class used with new to construct the object is where Java starts its search for the method.
Student: So then the second time, the receiver (or this) would be referring to @1002, so it would find the Circle one?
Prof: Correct.
Student: Wait so how does it find render()? That’s not on the Circle or Rectangle class.
Prof: Java stores the class and interface hierarchy. If it can’t find the method on the class, it looks at its parent class or implements arrows to search for the implementation. There must be an implementation if the program compiled; that’s what all the compile checks are for.

Student: OK, so if we had a render in Circle it would have used that one instead?
Prof: That’s exactly right, and you’ve just reconstructed overriding!
Student: Oh, I guess so.
Prof: There’s a name for this: dynamic dispatch. This is a defining feature of object-oriented programming. The class of the object, not the type of the variable, is used to determine which method to call. That makes it so one line in the program, like the call to draw() in render(), can actually call many different methods in one run of a program, depending on the receiver’s class.
Student: So that’s object-oriented programming?
Prof: Yes, I’d say a program that relies on dynamic dispatch is very much written in an object-oriented style.
Practice
Using these classes, whose method body runs for each call?
interface Post {
  String preview();
  default String badge() { return ""; }
  default String share() { return "Check this out: " + preview(); }
}
class TextPost implements Post {
  String message;
  TextPost(String message) { this.message = message; }
  public String preview() { return message + badge(); }
}
class PinnedPost extends TextPost {
  PinnedPost(String message) { super(message); }
  @Override
  public String badge() { return " [pinned]"; }
}

Post t = new TextPost("Free pizza in the CSE lobby");
Post p = new PinnedPost("Exam moved to Friday");
