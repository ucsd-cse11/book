Self-Referential Data

Student: Professor, I want to get the hard stuff. The real stuff about programming, the can’t-fake-it, no-nonsense big ideas. Stuff like recursion. My friends in upper division classes are always talking about that.
Prof: Good news! We’ve done recursion already.
Student: What?
Prof: We wrote our first recursive methods the last time we talked. And we’ve been making recursive data since we composed the French flag.
Student: How do you mean? Recursion is the hardest topic in CSE11. That’s what everyone says.
Prof: Then you’re doing great, as long as you understood our last conversations!
Student: Which parts?
Prof: Well, let’s bring up an example again and talk through a definition.
Prof: So, in terms of definitions:
  • The And record is a recursive datatype: it both implements ImageQuery and it has a field of type ImageQuery. That means a field of an And record can itself be an instance of And.
  • The matches method is a recursive method: when it calls matches on its fields, it may be calling the exact method it is in. That is, two stack frames right next to each other, each for the exact same method of the exact same class, just different receivers.
These are the two important definitions of recursion in the object-oriented programs we will write.
Student: Huh. OK. So the memory trace would have multiple stack frames for the matches method on And at the same time?
Prof: Right, that’s the idea:

Prof: That’s right.
Practice
Beside from the Pict library is recursive data too: its left and right are Picts, and its width method calls width on both of them.
record Beside(Pict left, Pict right) implements Pict {
  public int width() { return left.width() + right.width(); }
  // ...
}

Pict dot = new Circle(10, "red");
Pict box = new Rect(30, 20, "blue");
Pict pair = new Beside(dot, box);
Pict row = new Beside(pair, dot);
int w = row.width();
These are the calls of row.width() over time, with the receivers left out.

Which two calls are next to each other on the stack, running the same method of the same record?
  1. row.width() and the this.left.width() that returns 50
    Both run width from Beside: one on @1004, and the one it calls on @1003.
  2. the this.left.width() that returns 20 and the this.right.width() that returns 30
    @1001 is a Circle and @1002 is a Rect, so these are two different width methods, and neither one called the other.
  3. the two calls that return 20
    These run on the same object, @1001, but neither one called the other. They are never on the stack at the same time.
