Tracing Recursive Methods

Student: So we wrote this hasWord method recursively, that’s great. How would it work on, like, a really big chain of posts? I feel like I’m not totally clear on how it runs.
Prof: That’s a great question. Let’s first look at a memory trace for the call to r.hasWord("post") to see a small case, then we can think about generalizing to bigger ones.

Prof: So, notice there’s a moment where we have three active calls to hasWord. Two of them have receivers that are Repost instances, and one is a RegularPost instance (at the top). The stack “builds up” this computation, and then we’ll get a true from the topmost stack frame. We’ll then “unwind” through all the frames, returning true, using || to combine it with the false values that came back from the other calls to message.contains, and then finally result in true. In this example, I drew the strings on the heap, so you can see the receivers given to the contains method.
Student: OK, I think I get it. So in false || true, the false is coming from message.contains and the true is coming from the recursive call?
Prof: Good observation. That’s right. Do you think that will always be the case, or is that specific to this example?
Student: Hmmm, well the next example looks for "said", which is true on the first of the Repost instances. So there would be a true on the left, right?
Prof: Great question, let’s trace that one.

Student: Wait, where are all the recursive calls?
Prof: In this case, it stops after the first message.contains, because if the left value of || is true, the whole || expression stops before evaluating the right hand side. This is called short circuiting.
Student: So even though we wrote a recursive method, it might not actually make recursive calls?
Prof: Right – it’s a search that returns as soon as it finds a match, and might never actually look at original. But it will make the recursive call if it needs to. Can you think of an example input that would make one recursive call on r, but not two?
Student: Hmmm so it would have to match at the second repost but not the first… "she"?
Prof: Right! OK now back to your original question. What if there were hundreds of Repost instances in a chain, and we searched for a word that only appeared in the innermost RegularPost. What would the memory diagram look like?
