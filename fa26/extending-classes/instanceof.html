Student: Huh, interesting. So does it work for extends, too?

Student: OK, so how does that work? Does it like… search the class diagram?
Prof: Exactly. a instanceof C starts at the class of the object in a. If that isn’t C, it checks that class’s superclass and anything it implements, all the way up the diagram, looking for C. If a instanceof C, then the value stored in a could be stored in a variable of type C.
Student: Cool, where do I use that?
Prof: Honestly? Mostly you don’t.
Student: Mostly I don’t? What do you mean?
Prof: Well, most of the time we try to make our programs work out using the general interface types, like Pict or Place, for most variables. Then we just rely on the methods defined on them being present. Field lookups and class-specific work happen inside the class, and calling a method will select the class for the right object. So instanceof is honestly not needed much in well-written code.
Student: Hm… then why’d you show me?
Prof: Well, you’ll still see it in some places. And we need it to wrap up some of our discussion of Object and equals.

With the same classes, what is new Location() instanceof Park?
  1. false
    The search starts at the object’s own class, Location, and only goes up from there: to Place and Object. Park is below Location, so it never comes up.
  2. true, because Park extends Location
    The arrow from Park to Location says every Park is a Location. It doesn’t say every Location is a Park.
  3. It doesn’t compile
    A Location variable could hold a Park, so Java lets you ask. It refuses only when the answer could never be true.
