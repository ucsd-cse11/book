Here's a replacement that uses the **winding angle** instead of ray casting. Stand at `p` and turn to face each vertex in order around the outline, adding up how far you turn. If `p` is inside, you make one full turn, so the total is ±2π. If `p` is outside, you turn back as far as you turned forward, so the total is 0.

```java
  public boolean contains(Point p) {
    int n = this.outline.length;
    double totalAngle = 0;
    // Look at each edge (a, b), wrapping from the last point back to the first
    for (int i = 0, j = n - 1; i < n; j = i, i += 1) {
      Point a = this.outline[j];
      Point b = this.outline[i];

      // Points on the outline count as inside, like RectRegion and CircRegion
      if (onSegment(a, b, p)) { return true; }

      // Vectors from p to each end of the edge
      double ax = a.x() - p.x(), ay = a.y() - p.y();
      double bx = b.x() - p.x(), by = b.y() - p.y();

      // Signed angle turned going from a to b, as seen from p.
      // The cross product gives the sine part (and the direction of the turn),
      // the dot product gives the cosine part. atan2 combines them into an
      // angle between -π and π.
      double cross = ax * by - ay * bx;
      double dot = ax * bx + ay * by;
      totalAngle += Math.atan2(cross, dot);
    }
    // Inside: about ±2π (one full turn, either direction). Outside: about 0.
    // Comparing against π leaves plenty of room for rounding error.
    return Math.abs(totalAngle) > Math.PI;
  }
```

Why this passes the existing tests:

- **Boundary points**: the `onSegment` check runs first, just as before. Any point on an edge or at a vertex returns `true` before any angle is computed. This also means `p` never equals `a` or `b` when we call `atan2`, so we never compute the angle of a zero-length vector.
- **Starting point and direction** (`checkOutlines`): changing the starting vertex only reorders the terms in the sum. Reversing the outline negates every angle, so the total changes sign (2π becomes −2π). Taking `Math.abs` makes both directions give the same answer.
- **Skylines with collinear vertices**: an edge whose endpoints line up with `p` contributes an angle of 0 or ±π. Because `onSegment` already handled the case where `p` lies between them, the remaining case is 0, which doesn't affect the sum.
- **Rounding**: each `atan2` is accurate to within a few ulps. With at most about 14 edges in these tests, the total stays far from the π threshold.

The tradeoff is that ray casting uses only arithmetic and comparisons, while this approach calls `atan2` once per edge. That makes it slower, and it gives an approximate total rather than an exact count. In exchange, it has no special cases for vertices that lie exactly at `p.y()`.
