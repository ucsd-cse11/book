Student: Professor, I was talking to AI about Java, and it kept bringing up the terms “pass by reference” and “pass by value”. What do they mean?

Professor: That's a great question, let's ask AI together. Claude, define “pass by value” and “pass by reference” for us?

=== Response (verbatim) ===
## Pass by value vs. pass by reference

Both terms describe **what a method's parameter is** when you call the method.

**Pass by value:** The method gets a *copy of the value* of each argument, stored in a new variable in the method's own stack frame. If the method assigns a new value to its parameter (`param = ...`), the caller's variable doesn't change.

**Pass by reference:** The parameter is *another name for the caller's variable itself*. If the method assigns to the parameter, the caller's variable changes too. Java doesn't have this, but some languages do, such as C++ (`int& x`) and C# (`ref int x`).

## What Java does

**Java is always pass by value.** The confusion comes from what the value *is*:

- For a primitive like `int`, the value is the number, such as `17`.
- For a reference type (arrays, `String`, records, classes), the value is a **reference**, like the @1001 in the book's memory diagrams.

So when you pass an array, Java copies the reference into the new stack frame. The caller and the method then hold the *same reference*. That is **aliasing**, from the "How Java Runs" chapter. This program shows both effects:

```java
void change(int n, int[] arr) {
  n = 99;               // changes only this frame's copy of n
  arr[0] = 99;          // changes the array on the heap: the caller sees it
  arr = new int[]{ 0 }; // changes only this frame's copy of the reference
  arr[0] = -1;          // changes the new array, which the caller never sees
}

void main() {
  int x = 5;
  int[] nums = { 1, 2, 3 };
  change(x, nums);
  System.out.println(x);        // 5
  System.out.println(nums[0]);  // 99
}
```

Here's what memory looks like right after the line `arr[0] = 99;` runs:

```
main()                 x = 5, nums = @1001
change(x, nums)        n = 99, arr = @1001

Heap
@1001: [99, 2, 3]
```

Only one array exists, and both frames refer to it. The next line, `arr = new int[]{ 0 };`, gives `arr` a new reference, @1002. The `nums` variable in `main` still holds @1001. If Java were truly pass by reference, that assignment would have changed `nums` too.

## Connecting it to the book

You've already seen this behavior:
- `discountInPlace` changed the contents of `regular`, because the `Menu` held the same reference.
- In the `retag` exercise, `this.tags = newTags` gave the field a new reference, but the array in `a` kept its old contents.

When an AI says "Java passes objects by reference," it usually means "methods can change objects you pass to them." That's true, but it's because the method gets a copy of a reference, not because Java has pass by reference. Some people call this "passing references by value." To predict what a program will do, draw the memory diagram: a new frame, with copies of the argument values in it.
