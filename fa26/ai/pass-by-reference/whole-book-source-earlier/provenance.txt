Student: Professor, I was talking to AI about Java, and it kept bringing up the terms “pass by reference” and “pass by value”. What do they mean?

Professor: That's a great question, let's ask AI together. Claude, define “pass by value” and “pass by reference” for us?

=== Response (verbatim) ===
Happy to help. Both terms describe what a method's parameter gets when you call the method. They come from comparing programming languages, so the clearest way in is the memory diagrams you already know.

**Pass by value:** the method's new stack frame gets a *copy* of each argument's value. The parameter is a separate variable. If the method assigns something new to the parameter, the caller's variable doesn't change.

**Pass by reference:** the parameter *is* the caller's variable, under another name. Assigning something new to the parameter changes the caller's variable too. Languages like C++ let you ask for this, using `int& n`.

**Java only uses pass by value.** But think about what the "value" of a variable is. For a primitive like `int`, it's the number. For an array or object, it's a reference like @1001. So when you pass an array, Java copies the *reference* into the new frame. Here are both cases side by side:

```java
void replace(int[] arr) {
  arr = new int[]{ 0, 0 };   // changes only this frame's arr
}
void zeroFirst(int[] arr) {
  arr[0] = 0;                // changes the array on the heap
}
int[] nums = { 6, 7 };
void main() {
  replace(nums);
  zeroFirst(nums);
}
```

- **`replace(nums)`:** the frame for `replace` starts with `arr: @1001`, a copy of what's in `nums`. Then the assignment makes a new array at @1002 and puts @1002 in `arr`, inside that frame only. `nums` still holds @1001, so it's still `[6, 7]`.
- **`zeroFirst(nums)`:** `arr` again holds a copy of @1001. This time the method doesn't change `arr`. It follows the reference and updates the array on the heap. Now `nums` and `arr` are aliases for one array, so `nums` becomes `[0, 7]`.

You've seen this already. `discountInPlace` changed `regular` because `pricesCents` held the same reference. `retag` changed only the `tags` field of the `Post`, and `a` kept pointing at the old array.

**Why AI tools say "pass by reference":** many people loosely say "Java passes objects by reference," meaning "the method can change the caller's object." That part is true, because the reference is copied. But under the strict definition it's still pass by value: no method can make the caller's *variable* hold a different reference or number. Some people call Java's approach "pass by sharing" to avoid the confusion.

To figure out what a call can change, draw the frames:
- The method can't change the variables in the caller's frame.
- It can change anything on the heap that it can reach through the references it was given, unless those objects are immutable, like records or `String`s.
