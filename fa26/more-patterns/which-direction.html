Two Ways to Recur

Student: I’m having trouble with a program where I followed the recipe.
Prof: Oh? Interesting, show me what’s up.

Student: OK so I wanted to have Posts that could have replies, but also keep track of what they replied to. So I started with:

class Post {
  String user;
  String message;
  int likes;
  ArrayList<Post> replies;
  Post replyTo;
}
Student: My plan was to set it up so when you make a reply, it gets added to the replies list of what it’s replying to, and also stores it as replyTo.
Prof: That makes sense to me! What’s the problem?

int totalLikes() {
  ... this.replyTo.totalLikes() ...
  for(Post p: this.replies) {

Student: Wait, it’s going to keep going back and forth between @1001 and @1003? Why?
Prof: That’s just what the code does – it keeps going into the loop for the calls on @1001, and finding the replyTo field on @1003, which calls back to @1001.
Student: So it’s like an infinite loop, but with recursion?
Prof: Right. We call it unbounded recursion or infinite recursion. It ends when the stack runs out. In this book that gets reported as an ArithmeticException, in your terminal it would report as a StackOverflowError. It happens when a method calls back to itself with the same arguments, and nothing has changed to stop it from doing the same calls again.
Student: So how do we write totalLikes if the normal recipe doesn’t work?
Prof: I think we need to say more what we want totalLikes to do! I think there are two different total likes definitions we could mean.
Student: Two different ones?
Prof: Right – do we want to know the likes in this post and its replies, or in this post and the posts it is replying to? Does it go “down” through all the replies, or “up” through what it is replying to?
Student: Hmm, and what changes?
Prof: Well, going through the replies only recurs on the replies field. Going the other way recurs only through the replyTo field.
A base case is a call that makes no more recursive calls. Use the memory picture above.
Going down through replies, which posts are base cases? Select all that apply.
  1. original, @1001
    original has two replies, so the loop makes two recursive calls.
  2. ada, @1003
    ada has one reply, thanks, so the loop makes a recursive call.
  3. grace, @1005
    Its replies list is empty, so the loop body never runs. There is no if for this base case.
  4. thanks, @1007
    Its replies list is empty, so the loop body never runs.
Going up through replyTo, which post is the base case?
  1. original, @1001
    Its replyTo is null: there is nothing above it to recur on.
  2. ada, @1003
    ada replies to original, so there is one more post above it.
  3. grace, @1005
    grace replies to original, so there is one more post above it.
  4. thanks, @1007
    thanks replies to ada, which replies to original.

Student: I see, so that doesn’t even look at original for the ada case.
Prof: Right! Can you think about what the other direction looks like?
Student: Maybe like this?
int likesAbove() {
  if (this.replyTo == null) {
    return this.likes;
  }
  return this.likes + this.replyTo.likesAbove();
}
Prof: Yup, you got it. So there are really two templates for this data definition. One for going up a thread of replies, and one for going down:
// down, through replies
... down() {
  ... this.likes ...
  for (Post r : this.replies) {
    ... r.down() ...
  }
}

// up, through replyTo
... up() {
  if (this.replyTo == null) {
    ... this.likes ...
  }
  ... this.likes ... this.replyTo.up() ...
}
