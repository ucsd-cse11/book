Introduction to throw

Student: Professor, every program so far says throws IOException in main — and we just kept adding it. What does it actually mean?

Prof: It means “this method may throw an IOException”.

We can easily make Java stop on its own errors, like trying to read a missing file. What it can’t do is notice when the data is wrong. A weight of −0.2 is a perfectly good double as far as Java is concerned — only we humans know that our gear can’t weigh less than zero.

Student: So we have to stop the program ourselves?
Prof: Exactly — and the statement that does it is throw:
throw new IllegalArgumentException("Gear weight cannot be negative: gloves weighs -0.2");
Prof: throw stops the method right here and the rest of the code in the method never runs. new
IllegalArgumentException(...) is the exception object — the thing you throw. And the message in quotes is the part you control: say what went wrong, and with what value.
Student: Let me see it in a program — a method that adds up the weight and refuses a negative one.

Student: It printed the total. So with good data, the throw line just sits there and never runs?
Prof: Right — throw only runs when the if says so. Now the same program with one bad weight:
Student: It stopped — and the total never printed.
Prof: That’s what throwing does: the method stops immediately, the lines after the throw don’t run, and the program ends with the exception’s type and message. The message is the whole point — without it, you’d just see a crash; with it, you see exactly which gear and which weight had an invalid value.
Student: And throws IOException — that’s the same idea in the method header?
Prof: Same idea, but with a rule Java enforces. throws declares that a method may throw that type of exception — and for a checked exception like IOException, the compiler makes you declare it. A checked exception is something that can go wrong even when the code is correct, like the file not existing. The compiler won’t let you ignore it — the method either handles it or declares throws, and the decision travels up to whoever called it.
Student: And IllegalArgumentException? main doesn’t declare that one.
Prof: Right — that’s an unchecked exception, and those never have to be declared. An unchecked exception means something broke the rules the code expects: a method got a value it can’t use, or the data doesn’t fit the format. The program just stops with a message that says what’s wrong.
Student: So now I can stop the program whenever the data doesn’t make sense — with a message that says what’s wrong.
Prof: Gosh, you’re getting good at this!
Student: I think I understand, but this all seems a bit clunky. Is there an easier way to automatically check the data? Say, make Gear not allow negative weights at all? Didn’t we do something like that before? …
