Reading a File

Student: Okay, the list lives in gear-list.txt now. But how does Java get those pieces back out?
Prof: With a Scanner. Two objects: a File names the file, and a Scanner reads from it:
File file = new File("gear-list.txt");
Scanner input = new Scanner(file);
Prof: A Scanner reads piece by piece — a piece is a run of characters between spaces. input.next() hands you the next piece as text, input.nextDouble() reads the next piece as a number, and input.hasNext() answers true or false: is there another piece? So the loop is: while there’s another piece, read a name and a weight:
Student: So hasNext() is what stops the loop — it doesn’t know how many pieces there are, it just keeps asking “anotha one?”
Prof: Exactly. And nextDouble() does two jobs at once: it takes the next piece and turns it into a number. Everything from a file starts as text, so you have to convert the numbers yourself — nextDouble() and nextInt() do the converting for you. Isn’t that handy?
Student: Yeah! And what about a name with a space in it, like “ice axe”?
Prof: A space separates the pieces, so a name can’t have a space in this format — “ice axe” would read as two elements, and the second one isn’t a number, which would cause problems. So just keep names to one word for now!
Student: Alrighty, and why do we need input.close() at the end?
Prof: The Scanner keeps the file open until you close it. In a short program like this one, forgetting wouldn’t leak anything — the operating system takes the file back when the program ends. But a program that keeps running, or opens lots of files, can run out of open files if it never closes them. So close it every time, as a habit.
Student: So for a Scanner, close() is mostly about being tidy?
Prof: Here, yes! But for a PrintWriter it’s different. Closing a PrintWriter also flushes out anything still waiting to be written, so that one really does matter at the end. You’ll see that when we talk about writing to files.
Student: And what about throws IOException on main?
Prof: Opening the file can fail — no such file, for instance. new
Scanner(file) throws a FileNotFoundException, which is an IOException, so throws IOException covers it. The full story comes when we get to throw. But first, let’s see if we can process a similar file with slightly different contents. For this exercise, we’ll also keep track of gear name, weight, and quantity (an integer).
