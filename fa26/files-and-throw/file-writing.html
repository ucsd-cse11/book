Writing a File

Student: Okay, so reading is a Scanner and next. Now for the gear I’ve already packed — how do I write that to a file?
Prof: With a PrintWriter. Same File to name it — and print and println to write, just like System.out:
File file = new File("packedGear.txt");
PrintWriter output = new PrintWriter(file);
output.println("tent 2.5");
output.println("stove 0.8");
output.close();
Prof: The .println() method writes the text to our file, which is stored in our PrintWriter object, and it automatically adds a newline at the end. The close() method finishes the file: if you forget it, the last lines might never land.

Student: You read it straight back — is that just to check it worked?
Prof: That’s a good habit to get into; after you write a file, read it back and look at it. If the lines aren’t what you expected, you find out now, not three steps later when another program reads the file.
Student: And throws IOException again, because writing can fail too?
Prof: Exactly … writing can fail in a few ways. The folder that we’re trying to write to might not exist. This would throw an exception.
Student: And what if we run out of space while trying to write to a file?
Prof: Surprisingly, PrintWriter does not throw an IOException when a write operation fails. Instead, it internally records that an error occurred. That means your program could sneakily continue running without telling you the file wasn’t written to successfully! PrintWriter provides a method called checkError() that lets you ask whether a writing error occurred, but you’d have to call it explicitly to find out.
Student: So we’ve talked about what happens when something goes wrong, but can we check for potential problems before trying to read or write a file? Like, how do I even know if a file exists?
Prof: Great question! You can check with file.exists(). Be careful though, a PrintWriter replaces the file if it’s already there — it starts fresh.
Prof: There’s one more catch…
Student: Oh yeah?
Prof: Just because a file exists doesn’t mean we can successfully read it! What if we don’t have permission? Or what if it’s a directory rather than a regular file?
Even sneakier, what if the file gets deleted or moved between checking whether it exists and actually opening it?
So we still need throws IOException or a try/catch block to handle the possibility that opening the file could fail.
