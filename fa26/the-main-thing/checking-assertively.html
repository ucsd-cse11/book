Prof: First of all, great job. You’re doing the right thing by checking your work, and you’re making a great observation here. Think about how bad this would get if you had a dozen methods like this! Printed output isn’t the right way to check things once programs get large.
Student: Yeah how do big companies manage this? They have tons of code, right?
Prof: Right! So the main thing people use here is something that:
  • Checks a result from our program against an expected result. These are called test assertions or just tests
  • Only prints or reports when things fail. That’s called a test harness or a test runner
The standard one for Java is called JUnit. The book runs a simplified version. The main function we need is assertEquals:
void assertEquals(value1, value2)
It’s somewhat special in that it can take and compare any two values (which is why for now I didn’t give them any type). It reports an error if the values aren’t equal, and does nothing if they pass.

Work out by hand how many seats each course has left, and write that as the expected value of its test.
record Course(String name, int maxEnrollment, int enrollment) {
  int seatsAvailable() {
    return this.maxEnrollment - this.enrollment;
  }
}

void main() {
  assertEquals(, new Course("CSE 11", 400, 385).seatsAvailable());
  assertEquals(, new Course("CSE 12", 200, 200).seatsAvailable());
  System.out.println("All tests succeeded!");
