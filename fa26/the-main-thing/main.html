Prof: Oh?
Student: You’ve shown me a bunch of programs and said they were Java programs. But when I run them using the java command, nothing happens or I get errors. Look at what happened in the terminal the other day; I made a file called DefineX.java and ran it:
Student: What gives?
Prof: You’re right, I haven’t told you the whole truth. There’s a good quote about this – “Education is the art of telling progressively smaller lies.” Cohen, Stewart, and Pratchet whimsically said that teaching often involves giving “a statement that is false, but which nevertheless leads the child’s mind towards a more accurate explanation”. I’ve fudged some details here, by saying things like “the book prints” instead of “Java prints”. So I tried not to say anything false, but I was definitely sneaky.
Student: That’s not reassuring, I’m not a child, and it seems like you’re just making excuses. Just tell me what’s going on!
Prof: OK so here’s the deal. We set up the book to be able to write examples very easily, so we allow writing a bunch of definitions, and the book prints them when you click “Run”. We’ll keep doing that! We want the examples to be short.
Prof: But when you use the java command on a .java file, it looks for a method definition a the top level called main. It calls that method to “start the program”, and whatever happens in the main method is the program’s behavior. And if main isn’t there, it gives an error like the one you saw.
