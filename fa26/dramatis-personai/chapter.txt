Claude, define “pass by value” and “pass by reference” for us?

Claude: **Pass by value**

The function receives a **copy of the argument’s value**. The parameter is a new, independent variable initialized with that value. Assigning to the parameter inside the function has no effect on the caller’s variable.

```c
void f(int x) { x = 10; }

int a = 5;
f(a);
// a is still 5
```

**Pass by reference**

The function receives a **reference to the caller’s variable itself**, not a copy of its value. The parameter becomes an alias for the caller’s storage location, so assigning to the parameter changes the caller’s variable.

```cpp
void f(int& x) { x = 10; }

int a = 5;
f(a);
// a is now 10
```

**A useful test:** can you write a `swap(a, b)` function that exchanges the contents of the caller’s two variables? With pass by reference, yes. With pass by value, no.

**The common confusion: passing references *by value***

Languages like Java, Python, JavaScript, and Ruby are often described as pass by reference, but they are **pass by value**. The value being copied just happens to be a reference (pointer) to an object. This is sometimes called **call by sharing** or **call by object reference**.

```python
def f(lst):
    lst.append(4)   # mutates the shared object; the caller sees it
    lst = [99]      # rebinds the local parameter; the caller does NOT see it

a = [1, 2, 3]
f(a)
# a is [1, 2, 3, 4]
```

- **Mutation is visible** because the caller and the callee both point to the same object.
- **Reassignment is not visible** because the parameter is a copy of the pointer, not an alias for the caller’s variable `a`.

So the key question is not “can the function change the object?” It is “**can the function change which value the caller’s variable holds?**” Only true pass by reference allows that.

**Quick reference**

|  | Pass by value | Pass by reference |
| Parameter is… | a new variable holding a copy | an alias for the caller’s variable |
| Assigning to the parameter affects the caller? | No | Yes |
| `swap(a, b)` possible? | No | Yes |
| Examples | C, Java, Python, JS (all args) | C++ `&`, C# `ref`, Pascal `var`, Fortran |

Note that C’s “pass a pointer” (`void f(int *p)`) is pass by value of a pointer. It *simulates* pass by reference, but the pointer itself is still copied.

**The definitions**

**Pass by value:** When you call a method, each parameter gets a **copy of the argument’s value**. If the method assigns a new value to the parameter, only the method’s own copy changes. The caller’s variable stays the same.

**Pass by reference:** The parameter becomes **another name for the caller’s variable itself**. If the method assigns to the parameter, the caller’s variable changes too. C++ (`int&`) and C# (`ref`) can do this.

**Which one Java uses**

**Java always passes by value.** The confusing part is that for arrays, Strings, and objects, the value being copied is a reference like `@1001`. The glossary already says this: a **value** is “anything that can be stored, passed, or returned, including primitives and references.” When you call a method, the reference is copied into the method’s stack frame, not the object.

So when people say “Java passes objects by reference,” it’s loose wording. What really happens is that **the reference is passed by value**. Two experiments show the difference:

```java
void zeroFirst(int[] arr) {
  arr[0] = 0;               // changes the array on the heap
}

void replace(int[] arr) {
  arr = new int[]{ 9, 9 };  // changes only this frame's copy of the reference
}

void main() {
  int[] nums = { 6, 7 };    // nums = @1001
  zeroFirst(nums);          // arr = @1001 (a copy of the reference)
  replace(nums);            // arr = @1001, then arr = @1002
  System.out.println(Arrays.toString(nums));  // [0, 7]
}
```

In a memory diagram like the book’s:

- **`zeroFirst`**: `nums` and `arr` hold the same reference, `@1001`. This is **aliasing**, from the Aliasing section: “updates through one reference are visible through all the others.” The caller sees `0`. This is why `discountInPlace()` works.
- **`replace`**: The assignment only changes `arr` in `replace`’s stack frame to `@1002`. `nums` in `main`’s frame is still `@1001`. If Java passed by reference, `nums` would now be `[9, 9]`. It isn’t.

Primitives work the same way. `void addOne(int n) { n = n + 1; }` never changes the caller’s variable, because `n` is a copy.

**The short version for the student**

> Java copies whatever is in the variable. For an `int`, that’s the number. For an array or object, it’s the reference (the `@1001`). Changing **the object** through the copied reference is visible to the caller. Changing **the parameter** to point somewhere else is not.

Claude: **Pass by value vs. pass by reference**

Both terms describe **what a method’s parameter is** when you call the method.

**Pass by value:** The method gets a *copy of the value* of each argument, stored in a new variable in the method’s own stack frame. If the method assigns a new value to its parameter (`param = ...`), the caller’s variable doesn’t change.

**Pass by reference:** The parameter is *another name for the caller’s variable itself*. If the method assigns to the parameter, the caller’s variable changes too. Java doesn’t have this, but some languages do, such as C++ (`int& x`) and C# (`ref int x`).

**What Java does**

**Java is always pass by value.** The confusion comes from what the value *is*:

- For a primitive like `int`, the value is the number, such as `17`.
- For a reference type (arrays, `String`, records, classes), the value is a **reference**, like the @1001 in the book’s memory diagrams.

So when you pass an array, Java copies the reference into the new stack frame. The caller and the method then hold the *same reference*. That is **aliasing**, from the “How Java Runs” chapter. This program shows both effects:

```java
void change(int n, int[] arr) {
  n = 99;               // changes only this frame's copy of n
  arr[0] = 99;          // changes the array on the heap: the caller sees it
  arr = new int[]{ 0 }; // changes only this frame's copy of the reference
  arr[0] = -1;          // changes the new array, which the caller never sees
}

void main() {
  int x = 5;
  int[] nums = { 1, 2, 3 };
  change(x, nums);
  System.out.println(x);        // 5
  System.out.println(nums[0]);  // 99
}
```

Here’s what memory looks like right after the line `arr[0] = 99;` runs:

```
main()                 x = 5, nums = @1001
change(x, nums)        n = 99, arr = @1001

Heap
@1001: [99, 2, 3]
```

Only one array exists, and both frames refer to it. The next line, `arr = new int[]{ 0 };`, gives `arr` a new reference, @1002. The `nums` variable in `main` still holds @1001. If Java were truly pass by reference, that assignment would have changed `nums` too.

**Connecting it to the book**

You’ve already seen this behavior:

- `discountInPlace` changed the contents of `regular`, because the `Menu` held the same reference.
- In the `retag` exercise, `this.tags = newTags` gave the field a new reference, but the array in `a` kept its old contents.

When an AI says “Java passes objects by reference,” it usually means “methods can change objects you pass to them.” That’s true, but it’s because the method gets a copy of a reference, not because Java has pass by reference. Some people call this “passing references by value.” To predict what a program will do, draw the memory diagram: a new frame, with copies of the argument values in it.

```java
record Bag(int[] counts) { }

```

Choose one:

- `addOne` could make `b.counts` hold a new array, so the record is mutable, not “immutable” as claimed.
- A record can’t change because it is “immutable”, so Java will report an error in `addOne`.

```java
import java.awt.Color;
import java.awt.Graphics2D;
import java.awt.image.BufferedImage;
import java.io.File;
import java.io.IOException;
import javax.imageio.ImageIO;

public class GermanFlag {

    // Official colors (RGB approximations from the German federal government)
    private static final Color BLACK = new Color(0x00, 0x00, 0x00);
    private static final Color RED   = new Color(0xDD, 0x00, 0x00);
    private static final Color GOLD  = new Color(0xFF, 0xCE, 0x00);

    public static void main(String[] args) {
        int width = 1000;                   // default width in pixels
        String outputFile = "german_flag.png";

        if (args.length >= 1) {
            width = Integer.parseInt(args[0]);
        }
        if (args.length >= 2) {
            outputFile = args[1];
        }

        int height = width * 3 / 5;         // official 3:5 aspect ratio

        BufferedImage image = createFlag(width, height);

        try {
            ImageIO.write(image, "png", new File(outputFile));
            System.out.println("Saved " + width + "x" + height + " flag to " + outputFile);
        } catch (IOException e) {
            System.err.println("Error writing image: " + e.getMessage());
            System.exit(1);
        }
    }

    public static BufferedImage createFlag(int width, int height) {
        BufferedImage image = new BufferedImage(width, height, BufferedImage.TYPE_INT_RGB);
        Graphics2D g = image.createGraphics();

        // Compute band boundaries so the three bands fill the height exactly,
        // even when height isn't divisible by 3.
        int band1End = height / 3;
        int band2End = 2 * height / 3;

        g.setColor(BLACK);
        g.fillRect(0, 0, width, band1End);

        g.setColor(RED);
        g.fillRect(0, band1End, width, band2End - band1End);

        g.setColor(GOLD);
        g.fillRect(0, band2End, width, height - band2End);

        g.dispose();
        return image;
    }
}
```

**How to run**

```bash
javac GermanFlag.java
java GermanFlag                     # creates german_flag.png at 1000x600
java GermanFlag 500                 # creates a 500x300 flag
java GermanFlag 1500 flag.png       # custom size and filename
```

**Notes**

- **Colors:** Black `#000000`, red `#DD0000`, and gold `#FFCE00` are commonly used RGB values for the official flag colors.
- **Proportions:** The official ratio is height:width = 3:5, and the three bands have equal height.
- **Uneven heights:** The band boundaries are computed as `height/3` and `2*height/3` rather than adding a fixed band height three times. That way, no rows are left blank at the bottom when the height isn’t a multiple of 3.
- **Dependencies:** It uses only the standard library (`java.awt` and `javax.imageio`). No graphical display is needed, so it also works on headless servers. If you run into AWT errors, add `-Djava.awt.headless=true`.

```java
import java.awt.Color;
import java.awt.image.BufferedImage;
import java.io.File;
import java.io.IOException;
import javax.imageio.ImageIO;

/** A simple picture: a fixed-size grid of colored pixels. */
class Pict {
    private final int width;
    private final int height;
    private final Color[][] pixels; // pixels[row][col]

    Pict(int width, int height, Color background) {
        if (width <= 0 || height <= 0) {
            throw new IllegalArgumentException("Pict dimensions must be positive");
        }
        this.width = width;
        this.height = height;
        this.pixels = new Color[height][width];
        fillRect(0, 0, width, height, background);
    }

    int getWidth()  { return width; }
    int getHeight() { return height; }

    Color getPixel(int x, int y)              { return pixels[y][x]; }
    void  setPixel(int x, int y, Color color) { pixels[y][x] = color; }

    /** Fill the rectangle with top-left corner (x, y) and size w x h, clipped to bounds. */
    void fillRect(int x, int y, int w, int h, Color color) {
        for (int r = Math.max(0, y); r < Math.min(height, y + h); r++) {
            for (int c = Math.max(0, x); c < Math.min(width, x + w); c++) {
                pixels[r][c] = color;
            }
        }
    }

    /** Save this picture as a PNG file. */
    void save(String filename) throws IOException {
        BufferedImage img = new BufferedImage(width, height, BufferedImage.TYPE_INT_RGB);
        for (int r = 0; r < height; r++) {
            for (int c = 0; c < width; c++) {
                img.setRGB(c, r, pixels[r][c].getRGB());
            }
        }
        ImageIO.write(img, "png", new File(filename));
    }
}

public class GermanFlag {

    static final Color BLACK = new Color(0x00, 0x00, 0x00);
    static final Color RED   = new Color(0xDD, 0x00, 0x00);
    static final Color GOLD  = new Color(0xFF, 0xCE, 0x00);

    /** Three equal horizontal stripes (black, red, gold) at the official 3:5 ratio. */

        int stripe = height / 3;
        Pict flag = new Pict(width, height, BLACK);
        flag.fillRect(0, 0,          width, stripe,              BLACK);
        flag.fillRect(0, stripe,     width, stripe,              RED);
        flag.fillRect(0, 2 * stripe, width, height - 2 * stripe, GOLD); // absorbs rounding
```

1. Define the data and write examples to make the representation clear
2. Identify the method you want to write
3. Write the method header and examples together to figure out what it’s **supposed** to do; placeholder values to make it run
4. Implement the method body and check it against the examples.

```java
record Point(double x, double y) {}
interface Region { boolean contains(Point p); }
record RectRegion(Point corner, double width, double height) implements Region {
  public boolean contains(Point p) {
    return p.x() >= this.corner.x() && p.x() <= this.corner.x() + this.width
        && p.y() >= this.corner.y() && p.y() <= this.corner.y() + this.height;
  }
}
record CircRegion(Point center, double radius) implements Region {
  public boolean contains(Point p) {
    double dx = p.x() - this.center.x();
    double dy = p.y() - this.center.y();
    return Math.sqrt(dx * dx + dy * dy) <= this.radius;
  }
}
record Union(Region a, Region b) implements Region {
  public boolean contains(Point p) { return this.a.contains(p) || this.b.contains(p); }
}
record Intersect(Region a, Region b) implements Region {
  public boolean contains(Point p) { return this.a.contains(p) && this.b.contains(p); }
}

Region lens = new Intersect(new CircRegion(new Point(0, 0), 2),
                            new CircRegion(new Point(3, 0), 2));

                        new RectRegion(new Point(2, 0), 2, 6));

  assertEquals(false, lens.contains(new Point(-1, 0)));
  assertEquals(true, plus.contains(new Point(3, 3)));
  assertEquals(false, plus.contains(new Point(1, 1)));
}
```

Claude: Here’s an implementation of `Polygon.contains` that uses **ray casting** (the even-odd rule), with a separate check so points on the outline count as inside:

```java
record Polygon(Point[] outline) implements Region {
  public boolean contains(Point p) {
    int n = this.outline.length;
    boolean inside = false;
    // Look at each edge (a, b), wrapping from the last point back to the first
    for (int i = 0, j = n - 1; i < n; j = i, i += 1) {
      Point a = this.outline[j];
      Point b = this.outline[i];

      // Points on the outline count as inside, like RectRegion and CircRegion
      if (onSegment(a, b, p)) { return true; }

      // Cast a ray from p to the right and count how many edges it crosses.
      // Only count edges that cross p's y value. Using strict > on both ends
      // means a vertex exactly at p.y() is only counted once.
      if ((a.y() > p.y()) != (b.y() > p.y())) {
        // x position where this edge crosses the line y = p.y()
        double xCross = a.x() + (p.y() - a.y()) * (b.x() - a.x()) / (b.y() - a.y());
        if (p.x() < xCross) { inside = !inside; }
      }
    }
    return inside;
  }

  // Is p on the segment from a to b?
  private static boolean onSegment(Point a, Point b, Point p) {
    // Cross product is 0 when a, b, and p are on the same line
    double cross = (b.x() - a.x()) * (p.y() - a.y()) - (b.y() - a.y()) * (p.x() - a.x());
    if (cross != 0) { return false; }
    // p must also be between a and b
    return p.x() >= Math.min(a.x(), b.x()) && p.x() <= Math.max(a.x(), b.x())
        && p.y() >= Math.min(a.y(), b.y()) && p.y() <= Math.max(a.y(), b.y());
  }
}
```

**How it works**

1. **Outline check.** For each edge, `onSegment` tests whether `p` lies on it. The cross product is zero only when `p` is on the line through `a` and `b`. The bounds check then makes sure `p` is between them. This is why the tests for corners like `(10, 10)` and edges like `(10, 15)` return `true`.
2. **Ray casting.** Picture a ray going from `p` to the right forever. Each time it crosses an edge, it moves from inside to outside or back again. An odd number of crossings means `p` is inside.

   - The test `(a.y() > p.y()) != (b.y() > p.y())` keeps only edges that span `p`’s y value. Horizontal edges are skipped automatically, which also avoids dividing by zero in the `xCross` line.
   - Because the comparison is strict on both ends, a ray that passes exactly through a vertex is counted once, not twice.

**Checking one case by hand.** For `(5, 15)` in `lShape`, only two edges span y = 15:

- the edge at x = 0, which is to the left of 5, so it doesn’t count;
- the edge at x = 10, which is to the right, so it counts.

That’s one crossing, which is odd, so the result is inside. For `(15, 15)`, both of those edges are to the left, giving zero crossings, so the result is outside.

The same approach works for any simple polygon, including concave ones like `lShape`, `staircase`, and `trapezoid`.

One caveat: the `cross != 0` test is exact. That works for the integer coordinates in these tests. With arbitrary decimal coordinates, rounding errors could make a point that is really on an edge fail the check. If that matters, you could compare `Math.abs(cross)` against a small tolerance instead.

```java
import java.awt.Color;

record Point(double x, double y) {}
interface Region { boolean contains(Point p); }
record RectRegion(Point corner, double width, double height) implements Region {
  public boolean contains(Point p) {
    return p.x() >= this.corner.x() && p.x() <= this.corner.x() + this.width
        && p.y() >= this.corner.y() && p.y() <= this.corner.y() + this.height;
  }
}
record Union(Region a, Region b) implements Region {
  public boolean contains(Point p) { return this.a.contains(p) || this.b.contains(p); }
}
record Polygon(Point[] outline) implements Region {
  public boolean contains(Point p) {
    int n = this.outline.length;
    boolean inside = false;
    // Look at each edge (a, b), wrapping from the last point back to the first
    for (int i = 0, j = n - 1; i < n; j = i, i += 1) {
      Point a = this.outline[j];
      Point b = this.outline[i];

      // Points on the outline count as inside, like RectRegion and CircRegion
      if (onSegment(a, b, p)) { return true; }

      // Cast a ray from p to the right and count how many edges it crosses.
      // Only count edges that cross p's y value. Using strict > on both ends
      // means a vertex exactly at p.y() is only counted once.
      if ((a.y() > p.y()) != (b.y() > p.y())) {
        // x position where this edge crosses the line y = p.y()
        double xCross = a.x() + (p.y() - a.y()) * (b.x() - a.x()) / (b.y() - a.y());
        if (p.x() < xCross) { inside = !inside; }
      }
    }
    return inside;
  }
  // Is p on the segment from a to b?
  private static boolean onSegment(Point a, Point b, Point p) {
    // Cross product is 0 when a, b, and p are on the same line
    double cross = (b.x() - a.x()) * (p.y() - a.y()) - (b.y() - a.y()) * (p.x() - a.x());
    if (cross != 0) { return false; }
    // p must also be between a and b
    return p.x() >= Math.min(a.x(), b.x()) && p.x() <= Math.max(a.x(), b.x())
        && p.y() >= Math.min(a.y(), b.y()) && p.y() <= Math.max(a.y(), b.y());
  }
}

// columns of the same width, standing side by side on the x-axis
Polygon skyline(int width, int[] heights) {
  Point[] outline = new Point[2 * heights.length + 2];
  outline[0] = new Point(0, 0);
  for (int i = 0; i < heights.length; i += 1) {
    outline[2 * i + 1] = new Point(i * width, heights[i]);        // top-left of column i
    outline[2 * i + 2] = new Point((i + 1) * width, heights[i]);  // top-right of column i
  }
  outline[outline.length - 1] = new Point(heights.length * width, 0);
  return new Polygon(outline);
}

        new RectRegion(new Point(i * width, 0), width, heights[i]));

}
```

```java
  public boolean contains(Point p) {
    return p.x() >= this.corner.x() && p.x() <= this.corner.x() + this.width
        && p.y() >= this.corner.y() && p.y() <= this.corner.y() + this.height;
  }
}
record Union(Region a, Region b) implements Region {
  public boolean contains(Point p) { return this.a.contains(p) || this.b.contains(p); }
}
// a right triangle with its square corner at (0, 0)
record RampRegion(double width, double height) implements Region {
  public boolean contains(Point p) {
    return p.x() >= 0 && p.y() >= 0
        && p.x() * this.height + p.y() * this.width <= this.width * this.height;
  }
}
record Polygon(Point[] outline) implements Region {
  public boolean contains(Point p) {
    int n = this.outline.length;
    boolean inside = false;
    // Look at each edge (a, b), wrapping from the last point back to the first
    for (int i = 0, j = n - 1; i < n; j = i, i += 1) {
      Point a = this.outline[j];
      Point b = this.outline[i];

      // Points on the outline count as inside, like RectRegion and CircRegion
      if (onSegment(a, b, p)) { return true; }

      // Cast a ray from p to the right and count how many edges it crosses.
      // Only count edges that cross p's y value. Using strict > on both ends
      // means a vertex exactly at p.y() is only counted once.
      if ((a.y() > p.y()) != (b.y() > p.y())) {
        // x position where this edge crosses the line y = p.y()
        double xCross = a.x() + (p.y() - a.y()) * (b.x() - a.x()) / (b.y() - a.y());
        if (p.x() < xCross) { inside = !inside; }
      }
    }
    return inside;
  }
  // Is p on the segment from a to b?
  private static boolean onSegment(Point a, Point b, Point p) {
    // Cross product is 0 when a, b, and p are on the same line
    double cross = (b.x() - a.x()) * (p.y() - a.y()) - (b.y() - a.y()) * (p.x() - a.x());
    if (cross != 0) { return false; }
    // p must also be between a and b
    return p.x() >= Math.min(a.x(), b.x()) && p.x() <= Math.max(a.x(), b.x())
        && p.y() >= Math.min(a.y(), b.y()) && p.y() <= Math.max(a.y(), b.y());
  }

  // the same outline, starting from point number start
  Polygon startingAt(int start) {
    Point[] result = new Point[this.outline.length];
    for (int i = 0; i < result.length; i += 1) {
      result[i] = this.outline[(start + i) % result.length];
    }
    return new Polygon(result);
  }
  // the same outline, backwards
  Polygon reversed() {
    Point[] result = new Point[this.outline.length];
    for (int i = 0; i < result.length; i += 1) {
      result[i] = this.outline[result.length - 1 - i];
    }
    return new Polygon(result);
  }
```

Claude: Here’s a replacement that uses the **winding angle** instead of ray casting. Stand at `p` and turn to face each vertex in order around the outline, adding up how far you turn. If `p` is inside, you make one full turn, so the total is ±2π. If `p` is outside, you turn back as far as you turned forward, so the total is 0.

```java
  public boolean contains(Point p) {
    int n = this.outline.length;
    double totalAngle = 0;
    // Look at each edge (a, b), wrapping from the last point back to the first
    for (int i = 0, j = n - 1; i < n; j = i, i += 1) {
      Point a = this.outline[j];
      Point b = this.outline[i];

      // Points on the outline count as inside, like RectRegion and CircRegion
      if (onSegment(a, b, p)) { return true; }

      // Vectors from p to each end of the edge
      double ax = a.x() - p.x(), ay = a.y() - p.y();
      double bx = b.x() - p.x(), by = b.y() - p.y();

      // Signed angle turned going from a to b, as seen from p.
      // The cross product gives the sine part (and the direction of the turn),
      // the dot product gives the cosine part. atan2 combines them into an
      // angle between -π and π.
      double cross = ax * by - ay * bx;
      double dot = ax * bx + ay * by;
      totalAngle += Math.atan2(cross, dot);
    }
    // Inside: about ±2π (one full turn, either direction). Outside: about 0.
    // Comparing against π leaves plenty of room for rounding error.
    return Math.abs(totalAngle) > Math.PI;
  }
```

Why this passes the existing tests:

- **Boundary points**: the `onSegment` check runs first, just as before. Any point on an edge or at a vertex returns `true` before any angle is computed. This also means `p` never equals `a` or `b` when we call `atan2`, so we never compute the angle of a zero-length vector.
- **Starting point and direction** (`checkOutlines`): changing the starting vertex only reorders the terms in the sum. Reversing the outline negates every angle, so the total changes sign (2π becomes −2π). Taking `Math.abs` makes both directions give the same answer.
- **Skylines with collinear vertices**: an edge whose endpoints line up with `p` contributes an angle of 0 or ±π. Because `onSegment` already handled the case where `p` lies between them, the remaining case is 0, which doesn’t affect the sum.
- **Rounding**: each `atan2` is accurate to within a few ulps. With at most about 14 edges in these tests, the total stays far from the π threshold.

The tradeoff is that ray casting uses only arithmetic and comparisons, while this approach calls `atan2` once per edge. That makes it slower, and it gives an approximate total rather than an exact count. In exchange, it has no special cases for vertices that lie exactly at `p.y()`.

```java
      new Point(0, 0), new Point(width, 0), new Point(0, height) });
  Region ramp = new RampRegion(width, height);
  int checks = 0;
  for (int i = 0; i < 100; i += 1) {
    for (int j = 0; j < 100; j += 1) {
      Point p = new Point(-5 + i * 0.5, -5 + j * 0.5);
      assertEquals(ramp.contains(p), outline.contains(p), "at " + p);
      checks += 1;
    }
  }
  return checks;
}

int checkRandomRamps(int count, int seed) {
  Random random = new Random(seed);
  int checks = 0;
  for (int r = 0; r < count; r += 1) {
    checks += checkRamp(1 + random.nextInt(40), 1 + random.nextInt(40));
  }
  return checks;
}
```
