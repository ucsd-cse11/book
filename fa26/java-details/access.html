Student: Visibility modifiers?
Prof: Yeah. So we haven’t really bothered to write them except one – public. We had to add that when we implemented methods from an interface, remember?
Student: Yeah I remember that. You told me to just write it and not question it.
Prof: So all fields and methods can have one of several visibilities, which affect which other classes can use them directly. The ones we’ve been encountering implicitly are:
  • private – the field or method can be accessed only within the class or within classes declared in the same file, for the kind of programs we write (ones with a void main())
  • No modifier given (called “package private”) – the field or method can be accessed only within the class or other classes in files in the same “package” (roughly a folder)
  • public – any context can access the field or method

Student: And why would you want things to be private? It seems like it just adds errors to your program. Things should just be visible.
Prof: You know, I partially agree with you. But there’s a good argument for keeping fields private, and it’s what most people actually recommend! The idea is that it limits where you have to look to see what happens to a particular field. If you want to ask a question like “does this int field only ever increase” that’s a very complicated question to answer if any code in a big program could change it. But if you have all the uses of the field in one place, you can audit that quickly.
Especially these days with agents adding code all the time, things like private help set up some boundaries so you can still check a guarantee like “my field only increases” even if thousands of lines of code are added outside that class.

Practice
Raster is a class in Pict.java with private fields pixels, width, and height, and methods width(), height(), and colorAt(x, y). In your program, r is a Raster and c is a Circle. Which of these lines compile? Select all that do.
  1. int w = r.width();
    width() is a method of Raster that it lets you call.
  2. int w = r.width;
    width the field is private, so only code inside Raster can use it.
  3. Color first = r.colorAt(0, 0);
    colorAt is how Raster lets you read one pixel.
  4. Color[][] all = r.pixels;
    pixels is private. Raster never hands out its array.
  5. Color col = c.color();
    A record writes an accessor method for every field.
  6. Color col = c.color;
    A record’s fields are private, even when you didn’t write the word.
A record’s fields are private and final. Which of these can code outside the record do?
  1. Read a field’s value, with its accessor method
    The accessor method is public, so anyone can read the value with it.
  2. Change a field’s value after the record is built
    final means no field update, not even inside the record, once it’s built.
  3. Read a field directly, with . and the field name
    From another file, the field itself is private. The accessor method is the way in.
