14.9 — Hashmaps

1

Hashmaps store values associated with unique keys. For Example:

class FunWithHashMaps {
    public static void main(String[] args) {
        HashMap<String, Integer> hRank = new HashMap<>();
        hRank.put("USA", 15);
        hRank.put("India", 126);
        hRank.put("Mexico", 36);
        hRank.put("China", 64);
        hRank.put("Mexico", 12);
        System.out.println("Hash Map: " + hRank);
    }
}

In this we can see that at the key "USA" we are storing the value 15, for "India" we store 126 and so on. When we write to the key "Mexico" for the second time and put 12, the 36 that was there is overridden to 12 and 36 is no longer in the hash map. This results in each key being unique because if a key is written to twice, the first value is simply lost.

Everything beyond this point is out of the scope of Fall 23 CSE 11 but is slightly more in depth on how hash maps work.

A hashmap uses a hash function, which you will learn about later in CSE12 should you take it, to convert any given key to an index in an array. Then it will store the value at this index. To find the value of a known key, we plug the key into the hash function as we did to put the element into the array and the function must return the same index given the same key so it will again return the original index. We can then find the desired value at this index.

Values at a given key can be overriden as each key must be unique. 

If multiple keys return the same index, there are multiple ways we have with addressing this issue including linear probing and seperate chaining which you do not need to worry about now. For now we can simply assume that our hash table will handle collisions and always return a value stored with a given key when it is told to retrieve the value that was prior stored with said key.
